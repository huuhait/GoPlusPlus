Decisions (coder):
- D1 `errors.MustError` bootstrap. Spec ERR-9 and LEX-9: the type lives in package `errors`; the plans give it to P05.15 (bootstrap std) and P13.02. Today there is no `errors` package, no `recover` and no unwinding, so a `MustError` value cannot be observed. Decision: make no value now. `panic_must(expr string, pos string, err error)` (GIR helper next to `panic_<kind>`, `LinkOnceODR`, `noreturn`, LLVM `cold`) prints ERR-9's first line `panic: must: <expr> at <pos>: <err.Error()>` to standard error and exits with status 2, like the bootstrap panic. Its three arguments are the fields `Expr`, `Pos`, `Err`, so P04.07's panic part (call becomes a throw) and P05.15 (the type, `Unwrap`, the trace) only change the helper's body. Both-sided Done-whens are in TODO P05.15, P04.07 (defer and panic part, `defer f!()`), P12.04 (`go f!()`).
- D2 Message pieces. `Expr` is the call as written without the `!` (made from the lexer's tokens of the call, not its bytes: comments dropped, literals copied unchanged, the source's own spacing, a comma before `)` dropped; a raw string's newline shows as `\n`), cut at 120 bytes at a character boundary with `...`; the scan reads at most 240 bytes and counts them in `LowerSteps`, so a nest of n `!` costs O(n) (stress test). `Pos` is the base name of the file and line:col of the call's first character. Not the checker's `str(E)` (internal to Sema, and it prints the `!`). The error's trace (ERR-14) is not printed: it needs the runtime (P05).
- D3 Panic path = the P04.04 pattern at the GIR level, not a new `AssertKind`: an `Assert` takes only integer Args (V065) and the code generator would need aggregate slots; instead `Body::bangPanic` stores error, expr and pos into three locals and jumps to ONE block per function that calls `panic_must` (ADR-0028 rule 3.3). P04.26 changes that one call. No new verifier rule (the shape is ordinary Switch/Goto/Call), so no V0xx collision with the other teams.
- D4 Cold. New `BasicBlock::Cold` (printer `(cold)`, bitstream field, no verifier rule). The code generator puts `branch_weights` 2000:1 on a bool `Switch` whose one side is cold; every `NoReturn` function gets LLVM `cold` (also `exit` and the other panic helpers). Rationale: a block flag is something a later pass (cold-block layout, outlining) can read; weights on the terminator could not carry it.
- D5 Error test = the itab word of the error is null. A non-nil interface that holds a nil value (a nil slice or map in a named type) is an error, as in Go. Go++ pointers are never nil, so the typed-nil-pointer case does not exist; tested with `type listErr []int`.
- D6 `return` in a `!` function is lowered by operand count (ERR-3): `lowerFailsReturn`. A result with no zero value is written as its zero bits (ERR-3 "left unset"). Named results are not updated on a failing return today: nothing can observe them until `defer` exists. The item (a failing `!` or `return v, err` sets the named results before deferred calls run; both sides, scenario prints `0 true`) is recorded in TODO.md, P04.07's defer part ("Named results and a failing return"), worded to move with it to P04.26. `func f!()` that ends without `return` returns a nil error.
- D7 Checker fix found on the way: `func main!()` / `func init!()` were accepted (internal error V063 later). Now E0131 "must have no arguments and no return values" (`Decl.cpp`), tested both sides (`sema/bang-main-signature.test`).
