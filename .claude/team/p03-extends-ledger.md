Task: P03.22 `extends`, method marks, no struct embedding in `.gopp` (ADR-0023). Stage 2a of the p03-lang batch (P03.22 → P03.24 → P03.25, one by one, owner decision 2026-10-29). 3 coders (c1 simplest, c2 robust, c3 architecture) → PM merge (Opus). All three put the parent as a hidden first field (`Var::IsParent`).
Branch: `task/p03-extends-merged`

Manager decisions (PM merge):
- M1 base: c3's memoized origin queries and linear lookup; no quadratic fallback; stress tests linear (default < 2 s, ASan too).
- M2 the parent part as a value is value slicing everywhere (c1's rule): only `&c.P`, a longer selector, and the child literal's `P: P{…}` part are allowed.
- M3 an abstract type is never held by value, also through a type argument (`Box[P]`, `Option[P]`, `[]P`, `map[K]P`); pointers and `View[P]` are fine; decided on real substituted types (TYP-19).
- M4 type switch `case *Card:` on a parent pointer works like the assertion (EXP-14, TYP-22 table rule).
- M5 an `extends` cycle gets its own error naming the cycle.
- M6 one dense code run from E0374.
- M7 union of tests + gaps (`!` signature, child value as interface, owning upcast accepted, generic-child override, one error after a `base` name error, .go embedding differential against go build).
- M8 out of scope, listed: Clone through a reference to a parent that has children (possible sliced clone, not memory-unsafe; owner question), Send/Sync labels (no CON-12 yet), borrow-conflict write through `*T` (P04.09), drop-order data for P04.22 (parent is the first field, drops last).
