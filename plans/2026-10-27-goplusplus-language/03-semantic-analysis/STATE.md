## Decision changes

- 2026-10-28 (ADR-0025, owner decision): new task P03.25 and design D3.15. Units of measure in the language, like F# but written `[UNIT]`: `unit KM = 1000 M`, `float64[KM]`, `100.0[KM]`, unit math with a canonical form, `+` and comparisons convert both operands to the finer unit, the untyped constant `0` fits every unit, exact units for assignment, exact integer scale conversions, `[U unit]` generics, `.In[U]()`, `@Symbol`. ADR-0024 decision 15 (no literal suffixes) stays. Task count 261.
- 2026-10-28 (ADR-0024, owner decision): new task P03.24 and design D3.14. Operator overloading, "full minus unsafe": the operator is the method name (`func (a Vec2) + (b Vec2) Vec2`); binary, unary, `==` (gives `!=`), `<=>` returning `int` (gives `< <= > >=`), `&&`/`||` (lazy with `func() T`), `[]`/`[]=`, `()`, `<-`, explicit `@Convert`, `range`, `++`/`--`, read-only `*x`, `@Right` for a number on the left, operator constraints in generics, and `gopp vet` for `==`/`<=>`. Blocked: `=`, `.`, `&x`, the comma and implicit conversions. Replaces the non-goal "no user-defined operator overloading". The number 23 is skipped on purpose (a parallel branch may add P03.23).
- 2026-10-28 (owner decisions): P03.22 also builds the generic constraint `T extends Parent` (ADR-0023 decision 15, GEN-12); a C++ class as a parent is checked in P08.16. P03.24 has no literal-suffix work any more (ADR-0024 decision 15).
- 2026-10-28 (ADR-0024, manager decisions on the open points): the conversion hook is the attribute `@Convert` on an ordinary method (not a method named `to`); `<=>` is built in for numbers and strings (like `cmp.Compare`); `@Right` is allowed on every binary operator except `&&`/`||` (non-commutative operators are written for the swapped order, e.g. `1.0 / v`); an optional in-place compound method with a pointer receiver (`func (m *Matrix) += (b Matrix)`) avoids the temporary. `select` with user channels, user `==` ignored for map keys, constraint-only operator interfaces and no `!` on operators are decided. The one open point left (literal suffixes from other packages) was closed later the same day: literal suffixes were dropped (see the units line).
- 2026-10-28 (ADR-0023, owner decisions): new task P03.22 and design D3.13. Single inheritance with `extends` (one struct parent, `@Virtual` / `@Abstract` / `@Override`, `base.M()`, up- and downcasts), and Go struct embedding is removed from `.gopp` files (error with a fix-it; `.go` files unchanged; interface embedding stays). P03.22 also rewrites every existing `.gopp` test that embeds a struct, including the embedded-field tests of P03.15 and P03.20. The phase stays `[~]`.
- 2026-10-28 (P03.17 review, owner decisions, ADR-0018 amendment): `Option[T]` is comparable when `T` is (both nil, or both set and equal; `Option[*T]` by address; `comparable`, struct fields and map keys follow; a non-comparable `T` allows only `== nil`; `o == 5` means `o == Option[int](5)`). A copy of a narrowed `Option` takes the value type (`if a != nil { p := a }` gives `*Node`; `var p Option[*Node] = a` stays an `Option`). Amendment points 3 and 4 (task P03.18): funcs and interfaces with methods are never nil like pointers (`error` and its aliases, `any`, `unsafe.Pointer`, maps, slices and channels keep `nil`; `Option[Logger]` / `Option[func()]` are the maybe forms; `@Required` on a func or method-interface field is an error), and flow typing also covers `v, err := f()` and the comma-ok forms when the value type has no zero value, and the known-non-nil stores into `error`/`any`/map/chan `@Required` fields.

- 2026-10-27 (ADR-0009, P03.02 spike): constant floats are exact rationals on `APInt` with a 512-bit binary float past 4096 bits, like `go/constant`; libbf is not vendored (D3.2).
- 2026-10-27 (P03.07 review, manager decisions): a field or element of an owned temporary is itself a temporary and can move out; through a `Shared[T]` temporary it is a place, and a ref into it is a ref into a temporary. A conversion that shares storage (same underlying owning type ignoring tags, to an interface, or through a type parameter) is checked as its operand; slice→array of owning elements needs ownership. Spec: EXP-2.
- 2026-10-27 (ADR-0007, build profiles): `//gopp:build` terms include the main module's active profile name (P06 D6.12).
- 2026-10-27 (ADR-0006, P01.15 owner decisions): constraints `Copy` and `Clone` (replace `trivial` and `clonable`), the `x.Clone()` method and `IsNil()` on every pointer kind, the `&d` range form, the loop-variable redeclaration error, `func f!() error` is an error, and returning a `ref` into a local is an error. ## Notes / blockers

- P03.23 (done, team build `p03-lang`, merged from three coders): declarations past a fixed nesting depth (`MaxDeclNest`, a count, so the result never depends on the thread or its stack) only get their NamedType and wait in `DeferredDecls`; a generic one gets its type parameters first (an instantiation needs them). A pending type is declared by `declarePending` only: when the outermost declaration is done, or when `under()` / `expandNamed` needs it; any other reference sees it pending, so a chain that names each type twice stays off the stack. `validTypeWalk` (types2 validtype.go with an explicit stack, no depth cut) reports what Go reports (only the first problem of a walk), then goes on silently and notes every cycle it closes (cut by `invalidateByValueCycles`), so a by-value cycle behind an earlier error (`type I struct{ i I }`, then `E`/`A` holding each other next to an I field) is broken too (it ran forever before, also on master). Plain named types are cached as valid or failed, and a generic type as valid or failed for opaque type arguments (an instance whose arguments are type parameters no enclosing instance gives a type), so rings and chains of plain or generic types cost linear time (30000 by value: 0.11 s; 26 s with the first merged walk). `isPinnedRec` keeps its own stack; the zero-value prewarm uses a set, and the query for a generic declaration goes on at the asking depth, so a chain of generic instances is prewarmed bottom up (`gchain 200000` crashed in `ZeroQuery::has` before, also on master). Go's instantiation-cycle check (`Mono.cpp`, types2 mono.go: vertices are type parameters, a component with a heavy edge is a cycle, iterative Tarjan, method receivers canonical, method signatures not counted, function and body instantiations included) marks the types of a cycle before any walk (see review round 2 below), and reports E0366 at the first type parameter of the cycle, as Go does, only for a package with no other error (types2 runs monomorph only if `firstErr == nil`; corpus `fixedbugs/issue48619.go` relies on it and passes now, as do 48018, 48656 and 48974). A type holding itself by value keeps E0140. The clone walk's 100000-instance cap and `CloneState` 3 are gone. Done-when: a ring of 30000 under a slice (and 40- and 5-slice rings), chains of 200000 forward and backward with a copy and a `Clone()`, a 200000 chain naming each type twice, 50000 generic types, and the invalid rings at 30000 (`decl-chains.long.test`, run by `check-long`); smaller sizes of each in the default suite (`decl-chains.test`, `decl-invalid-rings.test`: by value, defined types, generic, blocked behind I, one error each); both instantiation-cycle shapes (`instantiation-cycle.test`, `instantiation-cycle-errors.test`, `clone-walk-runaway.test`); all under `timeout`, also in the ASan build. Review rounds 2 and 3: a cycle found by the silent part of a walk no longer makes its types invalid there, and a walk that has not failed yet skips a failed key only if no by-value cycle was met below it (`FailedKeys` keeps that flag; otherwise the key is walked again, so the problem Go meets first is the one reported, also when the key reaches a type on the walk's own path first), so what is reported is what Go's walk reports, in every declaration order (`type A struct{ a A; b B[int] }` reports A and B; R12b and R12c match go build in all 6 and 24 orders, `valid-type-all-orders.test`), still linear (the invalid rings at 10000: 0.07 s); the zero-value and pinned walks treat instances on an instantiation cycle as leaves too (they overflowed the stack or ran forever on fuzzed programs), and the receiver check asks for the underlying type through a defined type that names another (`recv-deferred-by-alias.test`); round 4: a ring of right-hand sides found at a declaration is reported by the first walk that meets it, from the type that comes round again and at the instance's position, as Go names it (`noteDeclRing`/`reportDeclRing`, R22), and the variable-size question for `unsafe.Sizeof` answers an instance from its generic declaration (`varParams`, a fixpoint over the parameters held by value) without expanding it, so a by-value growing instance no longer overflows the stack (`sizeof-growing-instance.test`, R23); `invalidateByValueCycles` cuts what is left (for a local type right after its walk). An instantiation of a generic alias is a mono edge (an alias cycle Go rejects is E0366, and the sweep after an E0140 ends); the mono pass only marks the types of a cycle (`NamedType::InstCycle`, `onInstCycle`), which the walks that follow every instance (clone, `containsView`, `viewCopyHasPointer`, the sweep) treat as a leaf, so they stay valid and every other error is reported (Go prints E0366 only without other errors); a defined type named in an alias's right-hand side is declared after the alias (`InAliasRhs`, via the `DeferredDecls` list), so `type N0 [1]N5[int]; type N1 N5[int]; type N5[P any] = N1` reports "N1 refers to itself" in every order. Tests: `valid-type-orders` (r12, r13, r14 and valid-alias-of-literal, both orders), `instantiation-cycle-hides-nothing`. Not fixed (same family, out of scope): `gcSizeof`/`gcAlignof` (Sizes.cpp) still cut at depth 64 and answer one word for deeper by-value nesting.

  - *Loop fixpoint* (OWN-P10; Flow.cpp `flowLoopHead`, `flowLoopBack`, `flowLoopClean`): the state at a loop top is the meet of the state before the loop and the states at its back edges (the end of the body, every `continue` via `FlowTarget::Cont`, also `continue L`, and the end of the post statement, which is now checked after the body with the real state). The back edges are known only after the body, so the head starts from the entry state with assumptions tagged with the loop's region: a local the loop assigns keeps what the entry knows (`FlowState::TentN`; a narrowed use records a `TentNUse`), a checked result the loop rebinds with a possible checked form is pending tentatively (`Tent`). `flowLoopBack` records, per region, what each back edge says (`PendReal`/`PendEdge`, `NBad`/`NEdge`); `regionPendReal` (least fixpoint) and `regionNBad` (greatest fixpoint for "known", so failing is the least one) are reachability walks over the regions with a seen set, linear however deep the loops nest (`tests/sema/loop-fixpoint-deep.test`: 32 nested loops; a path-based walk was exponential). A loop region is decided once, when its loop ends (`flowLoopClean`, `regionFrontier`): a failure (or, for a pending value, support) is recorded in the region; otherwise its edge list becomes the open regions it rests on, and the lists in the state after the loop are cut down the same way (a fact that rests on nothing open holds for good; a pending value that rests on nothing open is pending on nothing). So a closed region is one step from the open ones and every list stays as short as the nesting: loops in a row and sibling loops inside one loop stay linear (R11, `tests/sema/loop-fixpoint-sequential.test`: 12800 loops in about 0.1 s, 8 s before; R17, `tests/sema/loop-fixpoint-siblings.test`: 800 sibling inner loops for an Option and a checked result in about 0.02 s, minutes before). Label regions (goto) still use `RealForms`. A move in the loop kills the name at the head; a function literal, `&x` or a pointer-receiver call keeps it out (`narrowable`). A tentative narrowing is used only where a use needs the value: where the Option itself fits (`assignment` to a type the Option is assignable to, a blank target, a variable whose type is inferred, a generic parameter that takes the Option once inferred with it (`Option[T]`, `Option[*T]`, a bare type parameter; R16), a conversion, `==`/`!=`, a `switch` tag, `print`, and the Option's own `IsNil`/`Get`), `unnarrowTentative` makes the use the Option again (its recorded type too), so a failed assumption never makes such a use an error and no type depends on it (a copy `p := o` there is an Option). The other uses are reported at the end of the body if the region failed, with the loop in the text; `flowLoopClean` drops a fact that rests on a failed region from the state after the loop, so the code after it sees the variable unchecked, as before. `knownNonNil` (`@Required` stores) never rests on an assumption.
  - *Known-nil `close`* (CON-6a, E0355): `FlowState::Nil` holds the local channels nil on every path (declared with no value or with `nil` / `(chan T)(nil)`, or assigned `nil`); met by intersection, killed by every assignment (`PendingKills`), by a loop that assigns the name (`flowLoopHead`), by a check `ch != nil` (`flowAddTo`), a move, and reset at a goto label. `knownNilChan` asks `narrowable` (package variables, fields, `&` aliases, names in `NoNarrowNames`, an implicit `&ch` of a pointer-receiver call or method value: `takesImplicitAddress`, R9) and also excludes parameters, named results and every name a function literal uses (`ClosureNames`); `defer close(ch)` and `go close(ch)` are checked.
  - *Temporary map* (E0353): `rejectTempMapWrite` asks `placeKind` (Temp: a call result, a literal, a receive, a field or element of one by value, a conversion of one; a `Unique[*T]` result's target is its own) for `m[k] = v`, `op=`, `++`, `delete`, `clear`; a `*T` or `Shared[*T]` result is a place.
  - *Map or slice inside an interface* (E0354), DIRECT writes only: `boxPlace` walks the syntax from the write target through fields by value (not through a pointer), array, slice and map indexes, slice expressions and sharing conversions down to a type switch or assertion binding (TYP-9's `isBinding`), an Option `Get` binding of an Option held in the box (`BoxGetBindings`, set where the binding is made, R12), or an assertion.
