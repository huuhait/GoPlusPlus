## Notes of finished tasks

- P04.19 (done, team build `p04-runner`, merged from three coders, base c3): library `compiler/lib/TestRun` (`Protocol.h`: versioned JSON lines, output in base64; `BatchCompile.h`: `gopp build -emit=obj` with no global state, on a thread pool; `ExecutorPool.h`: one thread per executor process, restart after a crash, `exit`, time-out or a state change it cannot undo, recycle after 64 programs; `Executor.h`: `gopp test-exec`, LLJIT with a fresh JITDylib per program; `Runner.h`: compile and run overlap). From c2: the executor's own descriptors at 900 and up, stdin `/dev/null`, every signal at its default, no core files, an output limit (`RLIMIT_FSIZE`, SIGXFSZ), merged stdout and stderr in write order, link errors as the sorted missing symbols, start failures with a time limit and no more starts after three failures in a row (every program then gets the same `internal` result), and the failure-mode tests (`runner-ends`, `-streams`, `-limits`, `-failures`, `-determinism`, ported to the JSON protocol). From c1: `ninja check-run-real` and the exact executor count with one executor (`runner-crash`). Manager decision M2: after every program that returns, the executor puts back fds 0 to 2, closes the descriptors the program opened, resets signal dispositions, mask, pending signals and the alternate stack, cancels interval timers, sets back umask, working directory, environment and resource limits, and asks for a new process when it cannot (a lowered hard limit); a forked child that returns from main ends there; what is not put back needs a real binary (the list is in the design doc); `runner-reuse.test` runs each change and a program that looks at it in one executor against real binaries. M3: a batch that fails in any way (exit status, cannot start, results that are not this batch's) makes every test run its program alone, with a warning (`runner-batch-fallback.test`, nested lit, three forced failures); the result key (sources, gopp binary, protocol) is proven both ways (`runner-key.test`) and a source changed after the batch is not served stale (`runner-batch.test`). M4: the normal suite counts executor processes started (work); the scaling check (CPU time, 1x/4x/16x, best of two) is in `runner-equivalence.long` with a measured quadratic control. Numbers (load 4): 107 programs in 0.21 s wall and 1.1 s CPU, as real binaries 0.34 s and 3.3 s; 1712 programs in 1.3 s wall and 16 s CPU, cost per program growth 1.06 (control about 4). Not done: arm64 programs in the JIT (QEMU stays real binaries); the cached runtime and std as extra JIT inputs (P05.01, P06); `gopp test`.
- P04.01 (done, team build `p04-gir`; base c3, verifier rules and run tests from c2, `symbolOf` from c1): GIR is its own library (`compiler/lib/GIR`, `include/gopp/GIR`; ADT, Support and Bitstream headers only, in `check-includes`): types (`Type.h`, uniqued in a `Context`, fixed-width, structs nominal), the MIR-shaped IR (`GIR.h`: locals, blocks, statements, terminators with `UnwindAction`, places with typed projections, rvalues, indexes instead of pointers, `NoUnwind`/`NoReturn` functions), `FuncBuilder` (`Builder.h`, the one way to make a body, computes rvalue types), the builder from the checked AST (`Lower.h`; reads `sema::Info` only; `Lowering::lowerType` is the one place a checker type becomes a GIR type, an unsupported type is E0439 once; `gir::symbolOf` is the one place a function gets its symbol, for P04.17), the verifier (`Verify.h`: rules V001 to V070, one decision point each, iterative and linear; runs at the end of `lowerPackage` (E0440), after every `readModule` and at the start of `lowerToLLVM`), the printer (`gopp build -emit=gir` / `-dump-gir`, `gopp gir dump`) and the D4.15 bitstream writer and reader (`Serialize.h`: IDENT, MODULE, TYPES, FUNC and INDEX blocks, a trailer with the index offset, version check, deterministic, selective read of one body). The builder runs on a 32 MB thread (a left-deep chain at the parser's height limit needs 7.1 MB under ASan). The design for P04.04 to P04.24 is `docs/design/gir.md`. Tests: `tests/gir` (`check-gir`), `tests/unit/GIR` (`VerifierTest`: both sides of every rule; `StressTest`: near-linear verifier and printer; `DeepTest`: `DeepChain.*` at the parser's limit through GIR and LLVM IR; `GIRTest`). Not done: a reader for the *text* form (the binary to text to binary round trip of D4.15 is binary to module to binary plus binary to text equal to builder text; the doc says why).
- P04.02 (done): `CodeGen` lowers GIR to LLVM IR (`LowerToLLVM.cpp`: one alloca per local, one LLVM block per GIR block, bool i1 in registers and i8 in memory, Go semantics of signed `/ %` by -1, shifts at or above the width, saturating float to int, wrapping add/sub/mul; Assert fails to `llvm.trap` until P04.04 has panics; `uwtable` on every definition; DWARF line tables from spans; the LLVM verifier on every result), emits objects and assembly (`Emit.cpp`), and links with the bundled LLD started as `gopp lld ...` (`Linker.cpp`, in-process `lld::elf::link` in a subprocess of gopp; crt objects and dynamic linker from the P00.12 probe; every link input checked first; the link line has no build id, so objects and executables are byte-identical for the same input). `println`/`print` evaluate all operands first (Go's order), format constants at build time and write each run of text with one C `write`; `@Extern("C")` is validated (E0442); package main needs `func main` (E0443). `gopp build [-emit=gir|girb|llvm|asm|obj|exe] [-o]`. Tests: `tests/codegen` (`check-codegen`), `tests/run` (`check-run`: hello, D4.12 semantics, empty/long/non-ASCII strings, println operands, evaluation order, exit codes, determinism, link flags), `tests/unit/CodeGen`. Drops, cleanup edges, `terminate` unwind actions and resume are refused with a message naming P04.09/P04.07.
- P04.04 (done, team build `p04-core`, merged from three coders, base c3): the core subset lowers to GIR and runs as `go run` does (`docs/design/gir.md` section 15): every scalar incl. complex with D4.12 (checks as `Assert`s with their message values and one shared panic block per runtime function and function, ADR-0028 3.3, calling a bootstrap panic written in GIR: Go's first line to stderr, exit 2; FMA contracted on arm64 as gc does: `contract` flags, a fence at explicit conversions, and `llvm.fma` for a product held in a temporary, written once and read once by a + or - in the same block or a block its block dominates (so `x*y + f()` and `a[i]*b[i] + c[i]` fuse; `t := x*y; t+z` waits for P04.13), because opt 0 has no combiner), several and named results, switch/labels/goto/for, structs and arrays (in memory in the code generator: memmove/memset, built in place, passed by address), raw pointers, `unsafe`, `Option[T]` (D4.5 layout, eq and hash glue in `Glue.h`), package variables in the checker's `CheckedPackage::InitOrder` and `init` functions in the given file order, println of floats/complex/pointers, `_GP` symbols through `symbolOf`. ## Decision changes

- 2026-10-30 (ADR-0029, owner decision): an owned `[]T` is four words, `{ptr, len, cap, allocator}`, and a map header stores its allocator (option A); option B (3 words like Go) is rejected because `append` and drop on an arena or custom-allocator slice would use the wrong allocator. D4.5 is updated; borrowed slices and views stay 2 words, `string` stays 3 (ADR-0026). New task P04.25 (wave 2); P04.04 and P04.05 still lower 3 words until then. `docs/design/gir.md` section 15 points to it.
- 2026-10-30 (P04.17, manager decision): symbol names live in their own library `compiler/lib/Mangle` (`gopp/Mangle`, above Sema, below GIR and CodeGen; bound by `check-includes`), not in GIR; D0.5's layout lists it. Open items stay with their tasks: the `_GP` check of `@Export` names (P04.18), names of local types, closures and `init` functions (P04.04, P04.07), DWARF linkage names (P04.12).
- 2026-10-30 (ADR-0028, P04.15): D4.6 keeps native EH and FastISel; P04.07 gets four EH lowering rules for FastISel (each `invoke` alone in its block before ISel, one landing pad per function driven by a cleanup-state index, one panic call per kind with per-check source positions, no pad for callees that cannot unwind) and a fallback-count test; P04.13 chooses the arm64 `opt 0` selector with the ADR's numbers; P04.18 gets the aggregate-ABI cost at `opt 0`. Proposed, for the owner only if P06.01 triggers it: patching FastISel (an LLVM build from source).
- 2026-10-28 (ADR-0025, owner decision): new task P04.24 and design D4.20, units lowering (units erased to the base kind, scale conversions as constant `fmul` or `mul`, type descriptors with the canonical and display form for boxed unit values, `fmt` printing). Task count 261.
- 2026-10-28 (ADR-0023, owner decision): new task P04.22 and design D4.18, lowering of `extends` (type tables only for types with `@Virtual` / `@Abstract` methods, indirect calls through parent pointers, free upcast, checked downcast, `base` calls, drop order child then parent). Depends on P03.22. Final-only hierarchies have no table; owning upcasts and downcasts there are checker errors (P03.22).
- 2026-10-28 (ADR-0024, owner decision): new task P04.23 and design D4.19, operator lowering (direct calls that inline, compound forms with one evaluation, lazy and eager `&&`/`||`, `range`, `<-`, `@Convert`, user literals, fixed mangling table). Depends on P03.24.
- 2026-10-28 (owner decisions): Q3 (Go mode and the borrow and concurrency checks) is deferred, Go mode is not a current focus. P04.23 has no literal-suffix lowering any more (ADR-0024 decision 15).
- 2026-10-28 (ADR-0024, manager decisions on the open points): the conversion hook is the attribute `@Convert` on an ordinary method (not a method named `to`); `<=>` is built in for numbers and strings (like `cmp.Compare`); `@Right` is allowed on every binary operator except `&&`/`||` (non-commutative operators are written for the swapped order, e.g. `1.0 / v`); an optional in-place compound method with a pointer receiver (`func (m *Matrix) += (b Matrix)`) avoids the temporary. `select` with user channels, user `==` ignored for map keys, constraint-only operator interfaces and no `!` on operators are decided. The one open point left (literal suffixes from other packages) was closed later the same day: literal suffixes were dropped (see the units line).
- 2026-10-28 (ADR-0021 amendment, owner decisions): (A) a call result borrows what the callee's body says (per-function borrow summary, fixpoint over recursion, stored in export data with the "writes this parameter" bit; fallback to "all borrow-capable arguments" only with no body; no lifetime syntax; a changed summary is an API change for P14); (B) one writable borrow of a place at a time (Rust's `&mut` rule, spec OWN-B9): conservative overlap, writable `*T` copies are reborrows, every raw `*T` is a tracked borrow, `Shared[*T]` read-only unless a cell type (`mem.Cell` / `Mutex`). Hidden aliasing leaves UB. P04.20 extended, D4.16 updated; no new task.
- 2026-10-28 (ADR-0022, owner decision): new task P04.21 and design D4.17, race-free concurrency checks (`Send` / `Sync` labels, `go` and channel rules, globals, shared handles, deadlock check) on the flow graph of P04.09 and P04.20.
- 2026-10-28 (ADR-0021, owner decision): new task P04.20, a borrow checker without lifetime annotations on P04.09's flow graph; P04.09's "use through a pointer taken in the same function" item moves into it.
- 2026-10-27 (ADR-0007, build profiles): D4.8's three build modes become the `opt` setting of build profiles (P06 D6.12); `dev` is now `opt 0`, the default of the `debug` profile.
- 2026-10-27 (ADR-0006, P01.15 owner decisions): the `view` types are renamed `ref` (layout table only; no layout change).
