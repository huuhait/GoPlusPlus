# GIR: the Go++ mid-level IR

GIR sits between the checked AST (`crates/gopp-sema`) and the Clang-23 C23/C++20 backend (`crates/gopp-codegen-c`, [ADR-0001](../adr/0001-implementation-language.md)). It is shaped like Rust's MIR and Swift's SIL: typed, a control-flow graph of basic blocks, values in *places*, computed by *rvalues*, and **not SSA** (Clang 23 builds SSA from emitted C23 stack locals when optimizing). This document is the contract for the middle-end crates: `crates/gopp-gir`, `crates/gopp-plugin-api`, and `crates/gopp-plugin-host`.

## 1. Where GIR sits

```text
 gopp_gir::Checked (the package, its files, the checker's tables)
        |  gopp_gir::lower_package       reads Info, never re-derives
        v
  gopp_gir::Module
        |-- verify_module (V001..V085)
        |-- MoveCheck + BorrowCheck + ConcurrencyCheck  (mandatory safety gate)
        |-- -fpass-plugin [PreDropElab]  --> verify_module
        |-- DropElaboration + gir-inline --> verify_module
        |-- -fpass-plugin [PostDropElab] --> verify_module
        v
  gopp_codegen_c::emit_c23  -->  clang-23 (-std=gnu23 -fuse-ld=lld)
        |
        +-- gopp_gir::gopx::{encode,decode}   (postcard + zstd + blake3, section 13; .gopx)
        +-- gopp_gir::print_module            (text, `gopp build -emit=gir`)
```

Rules that keep the layers apart:

- **`gopp-gir` has zero Clang, LLD, or FFI dependencies.** Cargo's crate graph enforces the boundary at compile time (`#![forbid(unsafe_code)]` in `gopp-gir`). Only `gopp-codegen-c` knows Clang-23 C23 syntax and driver flags, and only `gopp-cimport` touches `clang-sys`. The compile-time macro interpreter (`P09`) and external `-fpass-plugin` crates run directly on `gopp-gir`.
- **The builder reads the checker, it does not decide again.** The type of an expression is `Info::type_of`, a constant is `TypeAndValue::val`, and what a name denotes is `Info::uses` / `defs`. Nothing in GIR lowering looks a name up or works out a type. If a feature needs a fact the checker does not record, the fact is added to `Info`, never guessed in GIR.
- **One way to make a body:** `gopp_gir::FuncBuilder`. It computes the type of every rvalue in one place; `verify_module` checks every type independently.
- **Lowering runs side by side.** `lower_package` cuts the functions of a package into runs of at least `256 KiB` of source, lowers each run into a module of its own on a `rayon` worker, and merges the runs: the functions of the package first, in source order, then every type, string, global and declaration of another package where a walk over those functions first names it. A run asks the checker's shared tables once per type, callee and name and keeps the answers. The merged module is the same for any number of threads, and `verify_module` runs on it before it is returned.

## 2. Data structures

All nodes inside `crates/gopp-gir` refer to their parts by typed arena **index** (`la_arena::Idx`: `LocalId`, `BlockId`, `FuncId`, `TypeId`, `Spur`), never by raw pointer, so a body can be cloned, substituted, serialized, and compared deterministically. Structural types are interned in `gir::TypeInterner`.

```text
Module      Types, Name (package path), Files[], Strings[], Funcs[], Globals[]
Global      Name (symbol), Ty, Link, Mutable
            Parts[]: static data, one constant for each leaf of Ty; empty = zeros
Function    Name (symbol), Sig (a Func TypeId), Link, CC, NoUnwind, Inline, Loc
            Locals[] (0 = return place, 1..N = parameters, then the rest)
            Blocks[] (0 = entry; empty = a declaration)
            Scopes[]: the debug scopes, a tree (section 14)
Local       Kind (Return, Arg, Var, Temp), Ty, Name, Mutable, Owned, Glue, Loc
            Source (declared by the program), Scope, ArgNo, Origin, Deref
BasicBlock  Stmts[], Term, Cleanup, Catch, Cold
Statement   Assign(Dest place, Rvalue) | StorageLive(L) | StorageDead(L) | Nop
            Boundary: a copy made by GIR inlining (never read from a file)
            Prologue: entry-block setup emitted before body line numbers
            DropOld: store replaces a live owned place
            Scope: the debug scope it is in (section 14)
Terminator  Goto | Switch | Return | Unreachable | Call | Drop | Assert | Resume
            Scope, as a statement's
DebugScope  Block (a `{}` of the source) | Inlined (an inline site: Callee at Loc)
            Parent (an earlier scope; 0 = the function), Loc, Callee, Origin
Span        {File+1, Line, Col}: self-contained, needs no SourceManager
```

Design points:

- **Locals are stack slots, not SSA values.** A `Local` may be assigned many times; GIR needs no $\phi$ nodes.
- **Temporaries** (`Local::Temp`) hold intermediate results, carrying `StorageLive` / `StorageDead` and `Local::Owned` where lifetime and drop elaboration require them.
- **`StorageLive` / `StorageDead`** mark the extent of a source variable. The builder maintains a scope stack; leaving a scope by falling through, `return`, `break`, `continue`, or `goto` emits `StorageDead` for the locals of every crossed scope, innermost first (`exit_scopes`). Drop elaboration uses these exact exits (section 7).
- **Functions are separate objects with mangled symbols as names.** Calls name their callee as an operand (`Constant::Func` for direct calls, or a function-pointer `Place` for indirect calls). `gopp_mangle::symbol_of` (`crates/gopp-mangle`, [appendix A](../spec/appendix-a-symbol-names.md)) decides every symbol name in one place: `_GP...` for Go++ functions, methods, instances, closures, and glue; bare C names for `@Extern("C")` and `@Export("C")` thunks; `main` for the C entry point; and `_gopp_...` for compiler runtime helpers.
- **`NoUnwind` and `NoReturn`** sit on `Function` (lowered to `__attribute__((nothrow))` and `__attribute__((noreturn, cold))` in C23). A call to a `NoReturn` function may omit its return target (`Target == None`, verified by `V028`).
- **Calling convention (`CallConv`):** `Go` is the internal convention (`__attribute__((swiftcall))` on `amd64`/`arm64`, C fallback on `riscv64`/`wasm32` and for a signature with a value of 3, 5, 6 or 7 bytes after its whole words, [ADR-0030](../adr/0030-amd64-calling-convention.md), [calling-convention.md](calling-convention.md)); `C` is the target C ABI ([c-abi.md](c-abi.md)). `CallConv` is part of `Func` types (printed `fn "C"(...)` for C), and a function's `CC` equals its signature's (`V075`). A Go++ function reaches C only through a C-ABI thunk (`_GPTC...` or `@Export("C")`), and indirect `fn "C"` calls pass scalars only (`V076` until `P07.08`). Closure code pointers carry `has_env` (`fn env(...)`, `V078`), lowered via `__attribute__((swift_context))` on `amd64`/`arm64`.

## 3. Types

GIR types have fixed target width (`int` is resolved to `i64` on 64-bit targets or `i32` on `wasm32` via `TargetLayout`), carry nominal names only on structs and recursive `Rec` shells, and are cheap to intern, substitute, and serialize.

| Kind | Meaning | Language types it stands for |
|---|---|---|
| `Unit` | empty tuple, size 0 | `void` / no result; `struct{}` |
| `Bool` | 1 byte in memory (`bool` in C23) | `bool` |
| `Int(bits, signed)` | 8, 16, 32, 64 | all integer kinds; `int`/`uint`/`uintptr` take `TargetLayout::pointer_bits` |
| `Float(bits)` | 32, 64 | `float32`, `float64` |
| `String` | `{ptr *u8, len u64, backing *u8}`; fields 0, 1, 2 ([ADR-0026](../adr/0026-no-small-string-optimization.md) + [ADR-0032](../adr/0032-shared-buffers-and-borrow-engine.md): no SSO; a literal or empty string points to rodata/null with `backing == null`, a heap string points `backing` at its `{refcount, byte_cap}` header with atomic `refcount` and a trailing NUL byte, `TYP-13`, `SLC-5`) | `string` |
| `Ptr(T)` | single pointer | `*T`, `Unique[T]`, `Shared[T]`, `Weak[T]`; `unsafe.Pointer` is `*u8` |
| `Slice(T)` | `{ptr *T, len u64, cap u64, backing *u8}`; fields 0..3; 4 words ([ADR-0029](../adr/0029-slice-and-map-allocator-word.md) + [ADR-0041](../adr/0041-values-are-copied.md)). `backing` is null for a nil or empty slice and for a `&s[i:j]` view, and otherwise points to the header `{alloc_cap, alloc}` at the start of the buffer. One owner, no reference count (section 15) | `[]T` |
| `Array(T, N)` | `N` elements | `[N]T` |
| `Tuple(T...)` | C-aligned anonymous struct | multi-value results, `(T, error)`; `complex64`/`complex128` are `Tuple(f, f)` |
| `Option(T)` | `T` followed by a 1-byte `bool` flag, padded to `T`'s alignment; fields 0 (`T`) and 1 (`bool`) | `Option[T]` when `T` has no pointer/interface/func niche |
| `Struct(name)` | nominal struct; body set once (supports recursive pointers/slices) | defined structs and generic struct instances (`Type::type_args` carries generic arguments) |
| `Rec(name)` | self-naming nominal shell whose body may be any non-struct type referencing the `Rec`; canonicalized so identical recursive shapes share one `TypeId` | recursive non-struct definitions: `type S []S`, `type M map[string]M`, `type O Option[*O]`, `type A [2]Option[*A]`, `type L [1]*L` |
| `Func(P..., R, has_env, cc)` | function pointer type with calling convention (`Go` or `C`) and optional closure environment flag | code pointer of a `func` value; C callback (`fn "C"`) |

**Single mapping point (`lower_type`):** `Lowering::lower_type` is the only function mapping `sema::TypeId` to `gir::TypeId` (memoized per `sema::TypeId`):

| Checker type | GIR representation |
|---|---|
| `bool`, integers, floats, `string` (untyped constants resolved to default types) | Direct table entry |
| `*T` | `Ptr(T)` |
| Defined type over a non-recursive basic/slice/map type | Underlying GIR type (methods lower to functions) |
| Defined struct type | `Struct` named by the symbol of its type descriptor (`_GPTiN4mainE5Point`), with declaration-order fields and C alignment |
| Defined non-struct type reaching itself | `Rec`, named as a defined struct is |
| `[N]T`, `[]T` | `Array(T, N)`, `Slice(T)` |
| `Unique[T]`, `Shared[T]`, `Weak[T]` | `Ptr(T)` (1-word payload pointer `T*`; for `Shared`/`Weak`, `{strong, weak, alloc}` precedes `top = (byte*)p + vptr.offset_to_top`, `TYP-19`, `OWN-P3`, `OWN-P4`) |
| `map[K]V` | `Ptr(Struct("gopp.map"))` (key/value sizes and glue passed via `gopp.mapinfo`, section 15) |
| `chan T` | `Ptr(Struct("gopp.chan"))` |
| `interface` | `Struct("gopp.iface")` = `{itab *u8, data *u8}`; `Option[I]` for a non-nilable interface with methods uses the same type with null `itab` as `nil` |
| `func` value | `Tuple(Func(env *u8, ...; has_env), *u8)` = `{code, env}` (`16` bytes on 64-bit); `Option[F]` uses the same type with null `code` as `nil` |
| `Option[P]` (`*T`, `Unique[T]`, `Shared[T]`, `Weak[T]`), `Option[I]`, `Option[F]` | Niche optimization: identical layout to `P` / `I` / `F` with null as `nil` (`Option` on already-nilable types like `[]T`, `map[K]V`, `chan T`, `any`, `error`, `unsafe.Pointer`, or `Option[U]` is rejected as `E0446`, `OWN-P9`) |
| `Option[T]` otherwise | `Option(T)` (`{value, set}`; padding and unset payloads never participate in `==` or hashing) |
| Unsubstituted type parameter | Unreachable in GIR (monomorphized per instance in section 10; internal error `E0440` if encountered) |

**Struct names.** A struct is found by its name, in a run and in the merge. A declared struct has the symbol of its type descriptor ([appendix A](../spec/appendix-a-symbol-names.md)): `_GPTiN4mainE5Point` for `main.Point`, `_GPTig0_1TF4mainE1f` for the first type `T` that the function `main.f` declares, `_GPTiIN4mainE3BoxiE` for `main.Box[int]`. That name is the same in every package and no other type has it; `gopp build -emit=gir | gopp demangle` reads it as `typeinfo for main.Point`. A struct without a name is `struct{a T; b U}` with the lowered field types. A defined non-struct type that reaches itself is reported as `E0439` until `Rec` lowering lands with the collections (`P04.13`).

Any construct not yet supported in a phase emits `E0439` (`err_gir_unsupported`) once at its span and substitutes a typed zero placeholder (`zero_of_expr`) so downstream statements produce no cascading errors; any missing checker invariant emits internal error `E0440`.

## 4. Places

A `Place` is a `LocalId` plus a `SmallVec` of projections; every projection records its resulting `TypeId`, so querying a place's type is $O(1)$.

| Projection | Meaning |
|---|---|
| `Deref` | `*p`; base must be `Ptr(T)` |
| `Field(N)` | field `N` of `String`, `Slice`, `Tuple`, `Option`, or `Struct` |
| `Index(L)` | element of `Array` or `Slice`, or `u8` byte of `String`; `L` is an integer `LocalId` (bounds check is an explicit preceding `Assert`) |
| `ConstIndex(N)` | constant element `N` of `Array` |
| `Downcast(N)` | variant payload `N` |

A **move path** (section 7) is a place containing only `Field`, `Deref`, and `ConstIndex` steps; runtime-indexed `Index(L)` places are never move paths.

## 5. Operands, constants, and rvalues

- **`Operand = Copy(Place) | Move(Place) | Const(Constant)`**
  - `Copy` reads a place without invalidating it (emitted for trivial `OWN-C1` values, for borrowed reads, for an argument passed as it is to a parameter the callee only reads, and for the source of a copy that is made, section 7).
  - `Move` transfers ownership without a copy (emitted for `move(x)`, `mem.Take` / `mem.Replace`, returning a local, and the last use of a local that can be copied, where the copy is skipped, [ADR-0041](../adr/0041-values-are-copied.md) rules 4 and 6).
- **`Constant`:** `Int` (truncated to bit-width), `Float` (IEEE-754 bits, rounded to `f32` for 32-bit floats), `Bool`, `Str` (index into `Module::Strings`), `Func` (`FuncId`), `Null`, `Zero` (all-zero value of any type), and `Global` (pointer to `Module::Globals[idx]`).
- **`Rvalue`:** `Use(Operand)`, `AddrOf(Place, Mutability)`, `Binary(BinOp, Operand, Operand)`, `Unary(UnOp, Operand)`, `Cast(CastKind, Operand)`, `Aggregate(AggKind, Vec<Operand>)`, `Len(Place)`.

All GIR operations carry **Go++ semantics** (lowered by `gopp-codegen-c` under `-fwrapv -fno-strict-aliasing -ffp-contract=off`):

- Signed `Div` / `Rem`: `MinInt / -1 == MinInt` and `MinInt % -1 == 0` (emitted via an explicit C23 helper check; non-constant zero divisors are guarded by a preceding `Assert(..., DivByZero)`).
- `Shl` / `Shr`: shift counts `>= width` yield `0` (or sign-fill for arithmetic `Shr`); signed negative counts are guarded by `Assert(..., NegativeShift)`.
- `Cast(FloatToInt)`: saturates on NaN (`0`) and out-of-range floats (`MinInt`..`MaxInt`, emitted via saturating C23 inline helpers).
- `Add`, `Sub`, `Mul`, `Neg`: wrap in two's complement (`-fwrapv`).
- Composite `==` and hashing (`String`, `Struct`, `Array`, `Complex`, `Option(T)`, `Interface`) lower to deduplicated `LinkOnceODR` glue functions (`add_eq_glue`, `add_hash_glue`).

## 6. Terminators, unwinding, cleanup, and `!`

```text
Goto(T)                                 Switch(op, [(v, T)...], otherwise)
Return                                  Unreachable
Call(callee, args, dest, T, unwind)     Drop(place, T, unwind)
Assert(cond, expected, kind, T, unwind) Resume
```

- **Calls and unwinding (`UnwindAction`):**
  - `Continue`: no local cleanup in this frame; unwind propagates to caller.
  - `Cleanup(B)`: unwind enters cleanup block `B`, which runs drops/defers and ends in `Resume` (emitted in C23 via `__attribute__((cleanup(...)))` scope guards under `-fexceptions`, or C++20 `try`/`catch (...)` frames when a function uses `defer`/`recover`).
  - `Terminate`: a panic inside a plain drop cleanup aborts the process.
  - `Unreachable`: callee is `NoUnwind` (`__attribute__((nothrow))`, including plain `@Extern("C")` functions and all calls under `-panic=abort`).
- **Cleanup & Catch blocks (`V023`–`V026`):**
  - Plain `Cleanup` blocks run only on unwind paths, enter only via `Cleanup(B)` edges (`V024`), cannot `Return`, and any calls/drops inside them use `Terminate` or `Unreachable` (`V025`).
  - `Catch` blocks (`BasicBlock::Catch`, implying `Cleanup`) implement `defer` + `recover()`: they run deferred calls LIFO, query `runtime.recover()`, and branch via `Switch` either back to normal return flow (when recovered) or to `Resume` (when unrecovered).
- **Fallible `!` propagation (`Info::Bangs`):** `f!(...)` lowers to `Call` followed by `Switch` on `err.itab == null`, branching on failure to a `BasicBlock::Cold` block (`__builtin_expect(..., 0)`):
  - `Return`: zeroes non-error return fields (`ERR-3`), writes `err`, and returns.
  - `Panic`: stores `(expr, pos, err)` into the function's shared `bang_panic` cold block, which calls `_gopp_panic_must(expr, pos, message)` with the message of the error (`__attribute__((noreturn, cold))`).
- **Runtime assertions (`Assert`):** Bounds, slice-bounds (`SliceAlen`..`Slice3C`, `SliceConvert`), nil, and division/shift checks carry message arguments (`V065`) and branch on failure to one shared cold panic block per check kind per function (`_gopp_panic_<kind>`). The first message argument of a bounds check is the index as the program wrote it, with its sign; the emitter also passes whether it is signed, so that a negative index reads as Go writes it ([runtime.md](runtime.md)).

## 7. Moves, drops, and drop elaboration

The GIR builder emits `Move` operands, `StorageLive`/`StorageDead`, and `Statement::DropOld` without inserting `Drop` terminators directly. After `MoveCheck`/`BorrowCheck`/`ConcurrencyCheck` (and `PreDropElab` plugins), `elaborate_drops` lowers ownership cleanups across the CFG:

- **Zero-on-move (no runtime drop flags for zeroable Go++ types, `OWN-R5`):** Owned non-parameter locals are zero-initialized in the entry block; moving a zeroable Go++ value copies its bytes and zeroes the source slot; every generated drop glue skips all-zero values and zeroes the slot on completion. Non-zeroable C++ values (`P08`) invoke their C++ move constructor and destructor.
- **What `elaborate_drops` rewrites:**
  1. Zero-initializes owned non-parameter locals in the entry block.
  2. Turns `StorageDead` of an owned local into `Drop` (innermost scope first, reverse declaration order).
  3. Turns `Statement::DropOld` (`x = rhs` on a live owned place) into evaluating `rhs` first (so `s = s` and `s = s[1:]` read `s` before it is dropped), dropping old `x`, then storing.
  4. Rewrites `Move(place)` into `Copy(place)` followed by zeroing `place`.
  5. Drops the by-value parameters the function owns (`OWN-C3` value parameters, plus any `OWN-C2` parameter that is the function's own value because the body does more than read it) at every `Return` and unwind path, while eliding known-zero drops within each basic block. A parameter the function only reads arrives without a copy and stays the caller's.
- **Category-aware transfers ([ADR-0041](../adr/0041-values-are-copied.md); [ADR-0032](../adr/0032-shared-buffers-and-borrow-engine.md) for strings and the borrow engine):** every assignment, store, argument, return, send, `go` argument and interface conversion gives the destination its own value, unless the program cannot notice the copy.
  - `OWN-C1` (trivial): bitwise `Copy`, no glue.
  - `OWN-C2` (can be copied, and the copy is more than the bytes: `string`, `[]T`, `map[K]V`, `Unique[T]` over a `T` that can be copied, a type with `drop()` and `Clone() T`, `Shared[T]`, `Weak[T]`, `chan T`, `interface`, `func`, and aggregates of them): **passed as it is** (no copy, 0 retain/release) to a by-value parameter the callee only reads, when the argument cannot change during the call (when it is read from an aliasable place that the call could write, the copy is made first; for a counted value that is a caller temporary retain, `PAR-1`); **handed over** (`Move`, no copy, 0 retain/release) on the last read of a local, from a temporary, and by `move(x)`; **copied** when the source is read again (`OWN-C2`). A copy of a counted value (`string` backing, `Shared[T]`, `Weak[T]`, `chan T`, `func` value) is a retain (`+1`). A copy of a `[]T` or `map[K]V` is a new buffer with a copy of every element or entry, each by its own rule. A copy of an interface value is a box of its own holding a copy of the value, by the rule of that value's type (`TYP-5`). A copy of a `Unique[T]` is a new allocation holding a copy of what it points to, and a copy of a type with `drop()` is a call of its `Clone() T`. Heap `string` backings, `chan` and plain `func` closures/cells use atomic refcounts (with a `refcount == 1` relaxed fast path on final free), while non-`Sync` `Shared[T]` uses a non-atomic refcount (`CON-3`). A `[]T`, a `map[K]V` or an interface box has one owner and no refcount.
  - `OWN-C3` (cannot be copied: types with `drop()` and no `Clone() T`, `@Pinned` types, C++ classes without a usable copy constructor, or aggregates containing them): **moved** by `move(x)`, on returning a local, and from a temporary (`MoveCheck` enforces `E0451` use-after-move via a hash-consed persistent 64-ary radix trie `PathSets` with $O(\Delta)$ branch joins); a plain copy is a compile error, also on the last use (fix-its `move(x)` and `&x`); **borrowed read-only** for `*T`, pure `@Operator` methods, `@Convert` methods, `Clone() T`, and `[]T` parameters the function only reads (`PAR-5`).
- **Interface boxes, borrowed interface arguments, closures, swaps, and in-place string append:**
  - Values exceeding 1 word or carrying ownership (`map`, `Shared`, `Unique`, types with `drop()` and `Clone() T`) are heap-boxed; the box holds only the payload, with one owner and no refcount (`TYP-5`, `TYP-8`); an interface argument that the callee does not keep is passed as `(itab, &value)` with zero allocation: the address of the caller's own variable when the callee only reads the parameter, of a copy in the caller's frame otherwise (`TYP-7`). Only a kept parameter is boxed on the heap (`iface_take`). Converting a `[]T` or `map[K]V` to a kept interface is a copy like any other: the box gets its own copy, or the value itself on its last use or with `move(x)` (`TYP-6`). A value that cannot be copied (`OWN-C3`) is never converted to an interface (`TYP-6`). A type switch or assertion gives its binding a copy of the boxed value, skipped when the binding is only read (`TYP-9`).
  - Parallel swaps (`a, b, c = ...`) check aliasing via `swap_may_alias`: provably disjoint `OWN-C3` places swap with zero clones; potentially aliased `3+`-way swaps need a copy, which an `OWN-C3` type does not have: a compile error (`E0452`/`E0453`).
  - `s += x` on a uniquely owned heap string (`backing != null && refcount == 1` with spare `byte_cap`) appends in place with trailing NUL (`STM-8`, $O(\log n)$ allocations).

**Today: who owns a value, and where it ends.** Strings, slices, maps and what holds them are freed; what a function owns is also freed where a stopped panic leaves it (below). A string shares its bytes, which a count in their buffer keeps: a copy of a string counts them once more (`_gopp_string_retain`), a string that ends once less (`_gopp_string_release`), and both are written with a test of `backing` before them, so that a literal calls nothing (`counted`, `Ends::Text`). A part `s[i:j]` counts the bytes too, and a `range` loop over a string holds a count of its own until it is left (`RNG-3a`). `s += x` is a call of `_gopp_string_append` with the address of `s` (`STM-8`): the string grows where it is when its buffer has one count and room behind its bytes, and gets a buffer half as large again otherwise, after which the old one is counted down; so a string that is built piece by piece is copied as often as its length grows by half, and a string that shares its bytes (a copy, a part, a literal) is never written to. An entry of a map is still joined into a new string. There is no `elaborate_drops` pass yet: the lowering writes every end itself, as a call of the **drop glue** of the type (`_GPTd<type>`: the parts of the value first, then `_gopp_slice_free` or `_gopp_map_drop`), and `Move` operands and `DropOld` are not in the module. The move check does not wait for the pass: it runs in the checker (below). The rules that the lowering keeps (`lower/slice.rs`, `lower/func.rs`):

- A value that holds what is freed has **one owner** (a string is such a value: it owns one count of its bytes): a variable or a parameter, a temporary, or the place inside another value.
- A **new value** (what a call gives, each of several results by itself, `make`, a literal, `append`, a conversion, a slice `x[i:j]`, a copy) is owned by its temporary (`fresh`, `FuncCx::temps`).
- Where a value is **given** (an assignment, a declaration, an argument, a receiver by value, a result, a part of a literal, an appended value) its temporary gives it up (`taken`). A place that the checker marks as copied gives a copy (`given`); a place marked as moved gives its value and is empty then, which is written after everything beside it is evaluated, so `return s, len(s)` reads `s` first; a place without a mark gives a copy, never its value. A local variable that is named directly in a `return` hands its value over instead of a copy: it ends with the function.
- An argument for a parameter that its function **only reads** is **lent** (`PAR-1`, `lower/facts.rs`): the caller stays the owner, nothing is copied or counted, and the function frees nothing. A function only reads a parameter if it never writes it or a part of it, takes no address of it, moves nothing out of it and does not return it; a copy that it gives away is a read. The fact is worked out for every function of the package before any is lowered (`Facts::lent`, `Shared::lent` by symbol), from its body alone, so it needs no fixed point. What the call could change is not lent as it is: only a temporary, or a place in a variable of the caller that nothing else reaches (`Facts::quiet`: no address of it is taken) and that is reached through no pointer; of any other place (a variable of the package, what a pointer leads to, a variable whose address is taken) the copy is made first and ends after the call. A function with a function literal, a `go` or a `defer` statement owns all its parameters. A call into another package knows no fact and gives every argument away, so the facts must go into the export data with `P06` before packages are linked together.
- A copy of a variable that is its **last use** gives the value itself (`Body::last_uses`, below), if the variable owns the value (it is no lent parameter, no element as it is, no other name of an element) and nothing else reaches it (`Facts::quiet`). The variable is empty from there on, like one that `move(x)` took the value of.
- What a temporary still owns when its **statement ends** is freed there; for a condition, before either way is taken; what is made to be walked by a `range` loop lives as long as the loop.
- A **variable** that owns is freed where its scope is left, by every way out (`exit_scopes`: the end of the block, `break`, `continue`, `return`, `goto`), the last declared first. A parameter by value that the function does more to than read is the function's own, since the caller gave a copy or the value itself. A plain range variable owns nothing.
- A place that is **assigned to** ends its old value after the new one is evaluated and before it is stored; `s = append(s, ...)` and `s = s[i:j]` keep what `s` has, and the second ends the elements that it cuts off. `delete`, `clear`, `copy` and a write to a map entry end what they overwrite.
- Places that **exchange** their values (`a, b = b, a`, which the checker marks in `Body::swaps`, `OWN-R4`) make no value and end none: the bytes of all are read first and stored as they are (`exchange`). With two places that is right also where the two are one place (`xs[i], xs[j] = xs[j], xs[i]` with equal indexes). With three or more, the bytes change places only if the places are variables of the function, no two of which can be one; otherwise two of them may be one place, a value could be lost and another kept twice, so each place gets a copy and ends what it had, as in any other assignment, and so does an entry of a map. A value that cannot be copied has no such copy: the lowering refuses the exchange (`E0452`, `FuncCx::uncopied`).
- A drop of an empty value does nothing, so a place that was moved out of needs no flag.

**Today: the move check, the last use and the lost write.** All are worked out by the checker (`gopp-sema`, `typecheck/moves.rs`) for every body after it is checked, on the syntax tree, so `gopp check` reports them. A value is moved as a whole variable only ([ADR-0041](../adr/0041-values-are-copied.md) rule 6), so the sets are sets of variables, not of paths. Each function, and each function literal by itself, is a graph of blocks; a block is a run of events in the order of evaluation: a variable is *read* (also when a part of it is written, when its address is taken, and where a literal that uses it is written), *given* (a copy of the whole variable that the checker marked in `var_modes`), *set* (assigned as a whole, or declared), *moved* (`move(x)` that the checker accepted), or an element of it is *written* (only for a parameter or receiver by value that is a slice or a map). The graph follows `if`, `for`, `range`, `switch` with `fallthrough`, `select`, labels, `break`, `continue`, `goto` and `return`; a `return` without values reads the results that have names, one with values sets them. Passes run over it with a work list, each only when the body has its events:

- **Forward, the variables that may be moved.** A read, a copy or a second `move` of one is `E0451` (`OWN-R5`), with a note at the `move`; one report per block and variable. A whole assignment gives the variable a value again.
- **Backward, the variables that are read later.** A *given* event after which its variable is not read on any way is a last use. Three things are never one: a copy in a statement that reads the variable a second time (one statement may read its operands in any order: `f(x, x)`, `g(x, len(x))`); a copy of what a `range` loop walks, inside the loop, and of what a `switch` is on, while its cases are compared (the statement reads the value where it is); and a copy of a variable whose address is taken or that a function literal uses.
- **Backward again, the parameters that are read later.** A *written* event after which its parameter is not read, given, moved or returned on any way is a lost write: `E0490` (`PAR-1`, ADR-0041 rule 9), reported once for a parameter, at its first such write. The events are `xs[i] = v` and every other assignment to a place under the parameter, `xs[i]++`, `xs[i] += v`, `delete`, `clear`, and `xs = append(xs, ...)`. None of them reads the parameter for this pass, so a loop that only writes is seen through. Three writes are never reported, because something may see them: one inside a `range` loop over the parameter that has a variable for the elements, one to a parameter that a function literal uses, and one to a parameter whose address is taken.

A `move(x)` of a variable that a statement around it still reads where it is (the `range` loop over it, the type switch on it) is `E0264` (`OWN-B2`), said in the walk: the loop would go on with a value that is gone. This is the one case of the borrow check that is built.

**Today: the pointers of a function (`OWN-B1` to `OWN-B3`, `RNG-3`; first part of the borrow check).** The checker follows what the variables of a function point into (`typecheck/borrows.rs`), on the graph of `moves.rs`. A **place** is a variable and a way into it (`Step`: a field, an element with its index if a constant says it, what a pointer points to, what a handle holds); `&place`, a view `&s[i:j]`, a variable of a `range` clause written with `&`, a handle that is lent as a pointer, and the receiver of a method that gives a pointer back are **loans** of a place. The walk says where a variable gets what may hold loans (`Event::Holds`, with the `&place` and the variables in the value), where a place is changed (`Event::Changed`: assigned, grown by `append`, cleared, moved, declared again when a loop comes around, ended with the statement that declares it), and what is returned (`Event::Returned`). Two passes go over the graph: forward, which loans each variable may hold (a place behind a pointer of a variable is a place in what the variable points into); backward, which variables are read later. With both: a place is not changed while a variable that is read later holds a loan of the place or of a part of it (`E0509` assigned or moved, `E0265` grown or cleared, `E0510` ended or declared again); a change of a part beside the loan (another field, another constant index) and a write through the pointer itself are fine; a pointer that the place holds is replaced, not what it points to. A loan of a variable, a parameter by value or what a handle of the function holds is not returned (`E0278`); a pointer into what a pointer parameter points to is. **Loops (`RNG-3`):** a `range` loop over a slice, a map or a string reads its place until it is left; a change of that place in its body is refused where the walk writes it (`E0285`), by the loops around it that range over a place of the same variable, and a change through a pointer by the events of the body. An element or an entry may be written, and a string that is replaced where the loop cannot see it is kept by its count (`RNG-3a`). The steps grow with the input: what a variable holds ends with the statement that declares it, so a loop does not carry it around, and a change is looked at only where a variable with a loan is read later. **Through pointers:** a value that is read through pointers (`q.p`, `*q`, `w.h.p`) holds what the variables hold that the pointers lead into, one step for each pointer (`Source::Holder` with the number of pointers); what a call gives back may be anything that its arguments reach, and what is outside the function. A store through a pointer (`Event::Stored`: `q.p = v`, `*q = v`) is held from then on by the variables that the pointer leads into, so a variable that ends while another holds a pointer to it through such a store is `E0510` as after a plain assignment; and a variable counts as used later if one that points into it is. **What is outside:** a parameter holds a pointer to what is outside the function from the start (a loan of what the parameter points to), and the result of a call, a variable of a package and what is read through a pointer from outside are from outside too (`Source::Outside`). A store behind a pointer that leads out of the function, or that the function knows nothing of, takes no pointer into a variable of the function or a parameter by value (`E0513`: `cannot store a pointer into local in h.p: what h points to outlives local`); a pointer from another parameter may be stored there (`func set(h *Holder, p *T) { h.p = p }`). A change looks only at the loans of the part that it changes (`Known::under`), and what is found not to be used through other pointers is remembered while variables end together, so the steps stay with the size of the function; only a call takes as many steps as its arguments reach. **Callee first (`OWN-B3`):** the walk of a body does not run the passes. It hands back a **problem** for the function and for each of its function literals (`borrows::Problem`: the events, the graph, the sources, the changes, the loops), in which a call is a source of its own (`Source::Call`) with the function that it runs, if the checker knows it (`Callee`: a function of the package or of an imported one, a method of a declared type; not a function value, a method of an interface, of a type parameter or one that a child may replace, a conversion), and the sources of each argument kept apart. When every body is checked, `lent_all` puts the problems into groups of functions that call each other (Tarjan), each group after those that it calls, and solves the groups that wait for no other side by side, level after level. A function says what it does with the pointers that it is given (`Lends`): today, for each parameter, whether a result may point into what the parameter reaches (a returned loan of what the parameter points to; a result with a name counts where a `return` has no values). A call gives back what the arguments reach that the function may give back, from the value that is passed on (`pick(&x, &y)` that returns its first leaves `y` alone), and all of them where the function is not known. In a group each member starts as a function that gives nothing back and is solved again when what one that it calls says has grown, so a ring of functions takes as many solves as it has members. What a function says is kept for the packages that import it (`Package::lends` for functions, the type table for methods); a function without a problem gives nothing back. **What a call stores (`OWN-B5`):** a function also says of each pair of its parameters whether it may store what the second reaches behind a pointer that the first reaches (`Lends::stores`): a store, or a call that stores, whose places are behind one parameter and whose value comes from another (`func set(out **T, p *T) { *out = p }` says it of `out` and `p`). A call with an argument that leads to a place for a pointer (`Types::leads_to_store`: a pointer to what holds a pointer; the receiver of a method if it holds one) is an event of its own (`Event::Called`): the variables that the first argument of a pair reaches hold from then on what the second reaches, so `h.Set(&y)` and `set(&h.p, &y)` make `h` point into `y`, and `y` may not end while `h` is used (`E0510`). Where the first argument leads out of the function, no pointer into a variable of the function is given (`E0513`: `cannot give a pointer into x to set: the call may store it where it outlives x`), also where a method ties its receiver into what another argument reaches. What a parameter points to is stored behind another parameter, which the callers are told, and nowhere else outside the function: not behind a pointer from a call or a variable of the package (`cannot give what p points to to find().Set`). A function that is not known (a function value, a method of an interface that is `Local`, of a type parameter or of a type with a table) may store all that it is given behind every argument that leads to a place for a pointer; what it stores of one argument behind the same argument is taken to stay inside the function. A conversion, a built-in function and the methods that options and handles have of their own store nothing. **Generic code (`GEN-5`):** a generic body is walked once, and a value of a type parameter in it is followed as what may hold a pointer (`Types::may_hold_pointer`), so a generic function says what it gives back and stores as a plain one does (`id[X]`, `set[X](out *X, v X)`, a method of `Box[X]`), and a call of it is a call of a function that is known. A method of a type parameter is one that a value has: it is given the value, not the address of its receiver, and is a function that is not known. What is found in a generic body is true for every type argument only if what carries the loan holds a pointer for sure. Where only a type parameter in the type of the carrier says that it may (the value that is returned, the place or the argument that is stored, the variable that holds the loan: `Carrier`, whose type the report looks up), nothing is said in the body: the type parameter is held to it as to what is kept on the heap (`kept_where`), and a type argument with a pointer is refused where it is given (`E0512`: `cannot use *int for X: the function is not for a type with a pointer in it: cannot return a pointer into x`). `wrapped[X](wrap func(*int) X) X { x := 1; return wrap(&x) }` is fine with `int` and refused with `*int`. Every body with a variable that may hold a pointer is walked, so a function says what it gives back also where it takes no address (`func get(h Holder) *T { return h.p }`). **Function literals (`CLO-3a`, `CLO-4`):** a function value is followed like a pointer (`Types::may_lend`: what may hold a pointer, or holds a function value, also behind a slice, a map, a channel or a handle). A function literal uses the variables around it where they are, so its value lends each of them that may lend (a loan with the step `Captured`: the variable may be assigned, and not ended or moved while the literal is used) and all that they reach; a function value that is called is given first to its call, and gives back what it reaches. Where a literal is followed, only what its variables hold counts: it is returned (`func (a *V) Iter() func(...)` over its receiver: the caller is told as for a pointer), stored behind a parameter, or given to a call that does not keep it. A function says of each parameter whether it keeps a function value that it is given there longer than the call (`Lends::keeps`: it puts it into a variable of the package, a channel or a new goroutine, or gives it to a call that keeps it); a function that is not known keeps every one. Where nothing follows a literal, it uses no variable that may hold a pointer (`E0514`: `cannot keep a function that uses p`): in a variable of the package, in a channel, as what `go` runs, in a call that keeps it. This is less than `CLO-3a` refuses (no kept literal over a tracked borrow at all), and what it lets through is followed. A literal puts no pointer of its own or of its parameters into a variable around it (`Event::Left`, `E0513`). What only a type parameter says of the variable that a literal uses is held against the type argument. **Two pointers at a call (`OWN-B4`):** a call with more than one pointer among its arguments, the receiver of a method with a pointer receiver included, has the sources of what each points to (`Call::pointees`), and no two of them may point to one place: to the same place of a variable, or to a place and a part of it (`Known::aliased`, `E0515`: `cannot give &list[i] and &list[j] to swapNames: both may point to the same place in list`). Other variables, other fields and other constant indexes are apart; one pointer parameter given twice is not. What is read through a pointer, and what comes from outside the function, may be one value by its nature (`OWN-B10`) and is not held to this, so inside a function two pointer parameters are two places unless both were read through pointers by the caller. **What a call changes (`OWN-B2`, `OWN-B9`):** a function may change what a pointer that it is given reaches, and the caller does not see how. So a call is a change of its own (`What::Call`) of every place that an argument which may lend reaches, written through a pointer: a pointer into a part of such a place is not used after the call (`E0509`: `cannot call grow: it may change x, and q points into x and is used later`), and the call is refused under a loop that ranges over such a place (`E0285`). Another pointer to the same place stays good, as after a write through a pointer. A function says of each parameter whether it changes anything behind it (`Lends::changes`: a change whose place is behind the parameter, or a call that makes one), so `size(&x)` and a method that only reads leave the pointers of the caller alone; a function that is not known changes all. A function literal says which variables around it it may change (`Step::Captured(lends, changes)`): where it is called, or given to a call, those are changed, and what the pointers among them reach. The passes look at the loans of a changed part before they look at who holds them (`Known::lent`, `holders`), so many holders of a loan that a change does not break cost nothing. This is the part of `OWN-B9` that memory safety needs. Not built: the rule itself, that no second pointer to a place is used while the first is (`q := p; use(p); use(q)`): inside one function every pointer is followed, and nothing is unsafe without it. **Values with several pointers (`OWN-B10`):** two pointers that were read through other pointers, or that came from calls, may point to one value, and the walk does not tell them apart (`OWN-B4` lets them be given to one call). So through such a pointer nothing is pointed into that the value owns apart from itself: the elements of a slice, the entries of a map, what a `Unique` or a `Shared` holds, the value of an interface. Where a pointer is taken into a place (`&a.Items[i]`, a view, a `&` range variable, the receiver of a method that is given its address or of a method of an interface), the walk says which step first leaves the value (`place_with`) and, if a pointer is on the way to the value, records the way to it (`Borrow`, `Event::Borrowed`). The passes follow that way: behind a pointer that was read through another (two steps through pointers), or behind one that the function did not make and is no parameter, it is `E0491`; behind a parameter it is the parameter's, and the function says so (`Lends::borrows`), so that a call which gives such a pointer to it is refused too (`cannot give a to first: the function points into what the value owns`). A function that is not known points into all that it is given a pointer to, where the type owns anything apart (`Types::owns_apart`). By index, as a value, a pointer to a field of the value itself, and all of it through a parameter of the function stay fine. For this a function also says where its results point (`Lends::deep`, `Lends::outside`): `tail(xs *[]int) *[]int { return &xs[1:] }` gives what `xs` points to and nothing deeper or outside, so `tail(tail(xs))` is a view of `xs`. Arenas need nothing of their own here: a pointer from `mem.ArenaNew` comes from a call. **Jumps:** the variables of a statement end where the statement ends, and where a jump leaves it: a `break` or a `continue` ends those of the statements between it and its loop, a `goto` those between it and its label (`Walk::depths`, `label_depths`; for a label that comes later the jump goes through a block of its own, which is filled when the function is walked, `Walk::gotos`). So a pointer into a variable of a block is not used after a `goto` or a `break` with a label out of the block. Not checked yet: a literal that stores the address of one variable around it in another; a function that is not known and ties an argument into what the same argument reaches outside, or stores what a parameter points to where nothing says how long it lives; an insert into a map under a loop over it (the runtime ends the program, `RNG-4`), and `Reset` of an arena under pointers into it and the guard of a mutex (`OWN-B2`, `CON-15`), which wait for `mem.Arena` and `sync.Mutex`: a guard and a pointer from an arena are values with a pointer to what they came from, and are followed as such when the types are there.

**Today: where a pointer may be kept (`OWN-B5`, first part).** The walk above follows a pointer in the variables of a function only, so the checker keeps pointers out of every other place (`typecheck/own.rs`, `E0512`). **By the type:** `Types::holds_pointer` says whether a value holds a pointer where it is: a pointer, a `Local[T]` (which may be made of one), or a struct (with its parents), an array, an option or a tuple with one; what a slice, a map, a channel or a handle leads to is on the heap and is not looked into. A value of such a type is not put on the heap: not as the element of a slice literal, of `make([]T)`, of `append`, or of a part of an array taken as a value (`arr[i:j]` is a slice of its own, `OWN-S2`; the view `&arr[i:j]` is fine), not as the key or the value of a map literal or of `make(map[K]V)`, not as the element of `make(chan T)`, not as the argument of `NewUnique` or `NewShared`, and `Unique[T]`, `Shared[T]` and `Weak[T]` are no types for it (`E0494`). So `[]*Node` has no value but nil, and a list of pointers is an array (`[3]*Shape{&a, &b, &c}`) or a slice of handles. **By the value, for the variables of a package:** such a variable may hold a pointer, but only one into a variable of a package, which lives as long as the program. A value that is given to one, or to a part of one, in its declaration or in an assignment (also one of several, from a call with several results, and as the variable of a `range` clause) is `&v` or `&v.f` or `&v[i]` of an array for a variable `v` of a package, what such a variable holds, `nil`, a literal or a conversion of these, or what holds no pointer; the address of an element of a slice or a map or of what a handle holds is refused, since the variable may replace it. What a call gives is refused. `_` keeps nothing. **In generic code** a type parameter stands for a type that may hold a pointer, and a body is checked once, so the type arguments are held to what the bodies do (`typecheck/kept.rs`). `Types::held` says what a value of a type holds where it is: a pointer, or the type parameters that it holds a value of (`[2]T`, `Pair[int, T]` by its fields; not `func(T)`, `[]T` or `*T`). Where a value is put on the heap and holds no pointer but type parameters, each of them is **kept** there (a seed, with where and into what); so is one that `Unique[...]`, `Shared[...]` or `Weak[...]` is written for. Every instantiation, written or inferred, gives each type parameter a type argument (the records of the instantiation cycles, `mono_record`): an argument that holds type parameters makes them kept if the parameter is (`through[U]` calls `list[Pair[int, U]]`), and one that holds a pointer is remembered. A receiver names the type parameters of its type, so what a method keeps, its type keeps; a method with type parameters of its own is a function of its own for each receiver. After every body is checked (`kept_report`), what is kept is followed from the seeds through the instantiations, and each remembered argument for a kept parameter is `E0512`: `cannot use *int for T: a value of it is kept in a slice that grows`. So `Stack[*int]` is refused where `Stack` has a method that appends a `T`, and `Pair[*int, *int]` and a `Handler[*Req]` with a `func(T)` field are fine. What is kept is written into the type table for the packages that import this one. The seeds, the instantiations and the reports are taken in the order of the source, so the same is said however the bodies were checked side by side; a generated table holds each way to put a value on the heap, with each kind of type, to the same answer in plain and in generic code (`generic_code_keeps_a_pointer_where_plain_code_does`). Not checked yet: a function literal that uses a pointer or a variable of its function and is kept longer than them (`CLO-3a`), and a store through a pointer parameter (`*out = &x`, `mem.Swap`).

The sets of the passes are `Sets`: tries of 64 children per node in which equal sets are one node, so a join costs as much as its two sides differ and a fixed point is found by comparing two numbers. The steps grow with the source (`the_steps_of_moves_and_last_uses_grow_with_the_input_not_faster`: thousands of sibling blocks, long-lived variables, labels, and loops and branches nested 400 deep). Not done yet: a `move` of a variable that a function literal made earlier still uses is not refused (it waits for closures and the borrow check), and a copy that is the receiver of a method is never a last use.

**Today: what goes to another goroutine (`CON-1`, `CON-2`, `CON-14`; first part of the concurrency check).** The checker labels every type `Send` and `Sync` (`types/label.rs`, `CON-12`). A `go` statement gives the function, its receiver and its arguments to a new goroutine: each is a value of a type that is `Send` (`Checker::spawned`, `E0516`: `cannot give &x to a new goroutine: a *T borrows what it points to`), and a method with a pointer receiver is not started on a variable, because it is given a pointer to it (`cannot run srv.Run in a new goroutine`; the fix is a function literal, which keeps what it uses). The element type of a channel is `Send` (`Checker::sendable`, `E0517`), looked at where the channel type is written, once the types that need instances without end are marked; in generic code that asks for `[T Send]` (`GEN-11`). What a function literal that `go` runs uses of a pointer is the borrow check's (`E0514`). **What a goroutine uses (`CON-3`, `CON-13`):** a function literal that `go` runs uses the variables around it where they are, at the same time as the rest of the function. A variable that nothing touches afterwards is the goroutine's, and its type is `Send`. One that is still touched is shared: the goroutine does not change it, nothing changes it afterwards, and its type is `Sync` (`E0518`: `cannot use x in a new goroutine: the goroutine changes x, and x is used after the go statement`). A variable that may hold a pointer is the borrow check's (`E0514`). **What a kept function may change (`CLO-2`):** a plain `func(...)` value is `Send` and `Sync`, so one that is kept may run on another goroutine while the variables that it uses are used here. The loan that a function literal has of a variable around it says whether the literal, or another literal of the body, may change the variable, and whether its type may be shared (`Step::Captured(lends, changes, unshared)`). Where such a value leaves the function as a plain function (a result, a store behind a parameter, a variable of the package, a channel, a call that keeps it, a function value that `go` runs), a variable that is changed or may not be shared is `E0520`: `cannot keep a function that uses n as a func value, which may run on another goroutine: n is changed by it or by another function`. The checker notes each value with a plain function that is given to a place which holds none, a `Local[func(...)]` (`Checker::localized`, in `assignment`): there the function stays with one goroutine and may change what it uses. A literal that `go` runs itself is the goroutine's own (`CON-13`). A `Local[func(...)]` is a function value and no pointer (a `Local` interface may be made of one), so it may be kept in a slice; a call goes through it as through any function value (`value_called`), and no variable of the package is of a type with a `Local` in it. Not held to this: a variable that the function around changes by itself after a kept literal that only reads it is made. Not built yet: writes to variables of the package after `init` (`CON-18`), and all that needs the `sync` package (`CON-15` to `CON-17`, `CON-20`).

**Today: `defer`.** `defer f(args)` and `defer x.m(args)` for a function or a method of the package, `defer v(args)` for a function value or a function literal, and `defer` of the built-in functions `print`, `println`, `panic`, `recover`, and `delete` and `clear` of a map. The function looks for its `defer` statements before its body is lowered (`find_defers`). At a statement the receiver and the arguments are evaluated, each for an owner of its own (a copy where the checker marks one, the value itself from a temporary, on a last use or with `move`; a pointer receiver is the address), and put into the **record** of the statement, a slot of the function: `(ran, values...)` (`defer_call`, `Pending`). The deferred calls are made by a function of their own, `_GPC0_<function>` (`lower_deferred`): the literal with the number 0, which no literal of the source has. It takes the address of a tuple with the addresses of the records, goes through the statements from the last to the first, and calls those that ran: a statement that runs once at most runs after those before it in the source, so that is the order of `PAN-4`. It marks a statement as not run before its call, so a panic in the call makes the calls that are left and not this one again. The call takes the values of the record; what it gives ends at once, and an argument for a parameter that the function only reads is ended after the call, since the function does not end it. Where the function is left, by a `return` or at its end, it calls that function and then `_gopp_defer_pop` (`run_defers`); the values of a `return` are worked out before, and the variables of the function end after. Every result of a function with `defer` statements has a variable, also one without a name: the `return` puts its values into the results first (what a result had ends), a deferred call may read and write the results that have names, and what the caller gets is read from the results after the calls. A statement that may run again has no record in the frame: the statements of an outermost loop share a **list** (`find_defers` counts the lists; in a function with a label every statement is in one list, since a jump may run any of them again). Each time such a statement runs it makes a record in a cell, `(the first record of the list before, the number of the statement, values...)`, and that record is the first of the list from then on; the slot with the first record is what the tuple of addresses has for the statement. The function of the deferred calls goes through a list where its loop is among the statements (`deferred_list`): it takes the first record off, picks the call by the number of the statement, and lets the cell go after the call, until the list is empty. So the calls of a loop run last first, between those of the statements around the loop. The values of a `defer` statement are owned by temporaries while the rest of the statement is worked out, and by the record after that. Not built yet, each reported as `E0439`: a `defer` of `copy`, of `clear` of a slice or of `close`, a deferred call that has the address of another name of an element (an `&` variable of a range clause), and a call whose result may be a view.

**Today: variables of blocks that a `defer` statement borrows (`PAN-3`, `PAN-4`).** The walk over a body (`lower/facts.rs`) finds the variables of blocks that a deferred function literal uses, and those whose address a `defer` statement has as the receiver of its call (a method that does not take a value) or as `&x` among its arguments: `Facts::extended`. A variable of the whole function is not among them: it lives as long as the function anyway. Each such variable lives in a cell (§15), a new one each time its declaration runs, and its cell has more after the variable (`new_cell`): the number of the variable among those that were declared while the function ran, and what a list keeps of it. A `defer` statement that runs calls `_gopp_extend` for each variable that it borrows: the list of its block has the cell too from then on, once, so the variable is not ended where its block ends. A statement that does not run borrows nothing, and the variable ends with its block as any other. Every block of the function itself has a list, a slot that the outermost scope ends (`Ends::Extended`, `_gopp_extended_end`) where it ends the variables of the function that were declared before the block. So where the function is left, after its deferred calls, the variables of the function and the borrowed ones end together, the one declared last first; and a panic that leaves the function ends them in its cleanup blocks the same way. The list is there from the start of its block, because a call in a loop may be left by a panic while the list has variables of an earlier pass.

**Today: panics and `recover`.** There is no `Catch` block yet: a panic is stopped by the frame below, and `Cleanup` blocks only end values. A function with `defer` statements has a **frame** for the runtime, `(next, run, record, mark)` (`gopp_frame` in [runtime.md](runtime.md)). Its first block, which is written last because the records are known then, gives every record a zero, puts the addresses of the records and of the variables of its results into one tuple, fills the frame with the function that makes its deferred calls and the address of that tuple, and calls `_gopp_defer_enter(frame)`, which gives false. `panic(v)` puts `v` into an interface value as any assignment to an `any` does and gives it to `_gopp_panic` with the keys of the methods `Error() string` and `String() string`, by which the runtime finds what the value says; nothing follows the call (`lower/panic.rs`). A failed `Assert` is a panic of the runtime with its message as the value. The runtime calls `run(record)` of every frame on top of the stack as it is, the innermost first, as Go does; `recover()` is `_gopp_recover`, which gives a copy of the value and marks the panic as stopped. When the deferred calls of a frame have stopped the panic, the runtime goes on in the function of that frame: `_gopp_defer_enter` gives true there, and the function returns to its caller with what its results have. A slot that is read then must have its value in memory wherever a call may panic, and not in a register that the way back does not restore: the address of each result is in the tuple that the runtime is given, so Clang keeps it in memory at every call. The reasons for this form: emitted C has no `try` and `catch`; and a panic that nothing stops ends the program with the whole stack still there, so its trace starts where the panic started. With `-panic=abort` (`Checked::aborts`, `PAN-7`) a panic ends the program at once: a function with `defer` statements has no frame and does not tell the runtime of itself, it only calls the function of its deferred calls where it returns, and `FuncCx::unwind` gives `Continue` for every call, so there is no cleanup block and the emitter writes no record. The functions are not marked `NoUnwind` yet. Not built yet: `recover` stops the panic wherever it is called while the deferred calls of the innermost frame run, not only when the deferred function calls it itself.

**Today: what a panic that leaves a function ends (`PAN-5`, `PAN-6`).** Every call and every `Assert` that the lowering writes asks `FuncCx::unwind` for its `UnwindAction`: `Cleanup(B)` where the function owns something, `Continue` where it owns nothing, `Terminate` while the end of a value is written. `B` is the first of a chain of cleanup blocks, one for each place that owns: the temporaries that wait for the rest of their statement, the last made first, then the variables and the walks of maps of each scope from the innermost out, in the order in which a way out of the scope ends them. A block ends its place and goes to the block of the place before it; the last one is `Resume`. The blocks are shared: a place has one block however many calls there are, and a scope keeps the blocks of its places (`Chain`), so the work is in the number of places and not places times calls. A place that gave its value up is empty before the next call; where one is not empty yet, the call ends nothing of the function. In a function with a frame the last block of every chain asks the runtime whether the function goes on (`_gopp_defer_left`) and ends the results only if not, since the function returns them if it goes on. A call in a cleanup block has `Terminate`, and so has every call that ends a value on a normal way: a panic that leaves a `drop` method ends the program. The function that makes the deferred calls holds what a call leaves to its statement in a scope, so a panic in the call ends it too.

The emitter writes the cleanup blocks of a function as one function of C, `<f>_unwind`, and gives the function a record `gopp_owned` with `__attribute__((cleanup(<f>_unwind)))`: Clang calls it wherever the function is left, also by the unwinder of the system (`-fexceptions`). The record has a number, `state`, and the locals that the cleanup blocks use; it is the last variable of the function, so every other one is still there when it is called. Before each call the function writes the number of the block that unwinding starts with there (0 for `Continue` and before a `return`, -1 for `Terminate`), and `<f>_unwind` starts with a `switch` over it. `<f>_unwind` is `always_inline` and nothing else has the address of the record, so with optimization the number is no memory: Clang gives each call the landing pad of its own block, and a function that returns runs nothing more than before. On Windows the unwinder of the system does not run the cleanup blocks of the function that goes on after a stopped panic: that function calls `<f>_unwind` itself where it is at its mark again, and its record is in memory for that ([runtime.md](runtime.md)).

**Today: functions that can fail and `!` (`ERR-1` to `ERR-9`).** The type of a function that is declared with `!` has the error as its last result, as the checker has it, so its signature in GIR is that of the Go form. The function has no variable for that result (`FuncCx::fails`). A `return` with as many values as the source declares results gives a zero for the error; one with a value more gives that value as the error (`ret`, which works out the values, and `leave`, which sets the results that have variables, makes the deferred calls and ends what the function owns). A function that can fail and has no results returns no error where its body ends. `call!(args)` is the call, then a `Switch` on the first word of the error to a block that is marked cold (`unwrapped`). What that block does is what the checker found for the function around the call (`Body::bangs`). `Return`: the function returns the error with a zero for each other result, as `return zero..., err` would: `leave` is written there with the temporaries of the statement as they are (`aside`), and what follows the call is written as if that way were not there. `Panic`: the method of the error is called through its table for the message, the error ends, and `_gopp_panic_must` gets the call as the source has it without the mark, its file, line and column, and the message. The value of the expression is the other results: none, the one, or a tuple of them in a slot of its own; they are the caller's own as after any call. Each failing call writes its own way out, so a function with many such calls and many variables that own has the ends of the variables once for each call, as it has for each `return`. `defer f!()` (`ERR-11a`): the statement keeps with its call how an error ends (`Marked`). In a function that can fail the record also has the address of the result with the error, which every function with `defer` statements has a variable for. The function of the deferred calls looks at the error that the call gave: it asks the runtime whether a panic runs the call (`_gopp_panicking`), and if none does and the function has no error yet, the error becomes that of the function; else the error ends. In a function that cannot fail the error is the panic of `_gopp_panic_must`, with the call as it is written and its place. What such a call gives beside the error must own nothing. The trace (`ERR-14`): every way that a failing call with `!` takes, and no other, calls `_gopp_err_trace` with the two words of the error and the place of the call (`traced`); the words are given as they are, so the error needs no address and the other way is the call, a compare and a branch ([runtime.md](runtime.md)). Not built yet: `go f!()`, and `errors.MustError` as the value of the panic (`ERR-9`): the panic has its text.

**Today: copies.** Where the checker marks a place as copied for its new owner (`Info::var_modes`), the lowering gives the owner a copy: none for a value that is copied by its bytes, one more count for a string, `_gopp_slice_copy` for a slice of such values, `_gopp_map_copy` for a map, and for every other value the **clone glue** of its type. The glue is a function `_GPTc<type>` that takes the address of a value and makes the value a copy of its own: a slice gets its buffer and then each element its glue, a map its table (its record of the type carries the glue of the values), a struct each field that needs it, an array each element, an option what it holds. `lower/glue.rs` declares the glue where a function asks for it and checks then that every part of the type has one; the package makes each glue once, in a part of its own that is lowered after the functions and merged last, in the order of the symbols, so the module is the same for any number of threads. Glue is `LinkOnceODR` and has the convention of C, because the runtime calls it too (`_gopp_each` for the elements of a slice or an array, `_gopp_map_copy` for the values of a map). A struct type with a `drop` method (`OWN-R7`) is never copied by its bytes, whatever its fields are (`Memo::dropped`): its drop glue calls `drop` with the address of the value and then ends the fields that need it, and it is called for a value that was moved away too, which is all zeros and which `drop` must take (`OWN-R5`). If the type has the copy method `Clone() T` (`OWN-R6`), its clone glue calls it with the value and puts what it gives in its place; the method is lent its receiver, so one that does more to it than read is not supported yet. A type without the copy method is never copied: the checker refuses the copy, and a map with such values is not supported yet, because the copy of a map copies them. Not supported yet either (`E0439`): a `drop` method of a type that is no struct, and a `drop` or a `Clone` method of another package. **`Unique[T]` today (`OWN-P2`, `OWN-P6`, `OWN-P8`):** the handle is a pointer to a box on the heap that holds the value first, so the address of the box is the address of the value. In GIR the box is a struct with the symbol of the type (`_GPTiIu6Unique<T>E`, one field), and the handle a pointer to it: no `*T` of the source has that type, which is how the lowering tells the owner from a pointer (`Memo::uniques`; `flat` says that it owns). `NewUnique(v)` works `v` out for a new owner and puts it into a box (`_gopp_iface_box`, the box of an interface value: so many bytes of its own). A field or a method reached through the handle follows it to the first field of the box (`deref`, `pointee`). In a place where a `*T` fits, also as an `Option`, the handle is lent: a cast of the same address, and the handle stays the owner. The drop glue ends the value by the glue of its type and frees the box (`_gopp_box_free`); the clone glue makes a box of its own with the bytes and then calls the clone glue of the value (`Cloned::Unique`); a handle that gave its value up is nil, and the glue does nothing for it. `Option[Unique[T]]` is the handle itself, nil when it is unset, and has the glue of the handle. `==` compares the addresses. A method is given the value at the handle, or the handle as the address of the value if it takes an address (`receiver`). **`Shared[T]` and `Weak[T]` today (`OWN-P3`, `OWN-P8`):** each is a handle of the same kind with a box type of its own (`_GPTiIu6Shared<T>E`, `_GPTiIu4Weak<T>E`; `Memo::shareds`, `Memo::weaks`), so a `Shared` is reached through and lent as a `*T` like a `Unique` (`Memo::held`), and a `Weak` is not. The runtime keeps two counts in front of the value (`runtime/shared.c`): the `Shared` handles, and the `Weak` handles with one more for all the `Shared` handles together. `NewShared(v)` is `_gopp_shared_new` with the bytes of `v`; `NewWeak(s)` reads `s` where it is and counts one `Weak` handle more; `w.Lock()` is `_gopp_weak_lock`, which gives one more `Shared` handle if the value has not ended and nil if it has, and its result `Option[Shared[T]]` is the handle. The clone glue of either handle counts one more (`Cloned::Shared`, `Cloned::Weak`). The drop glue of a `Shared` counts one less (`_gopp_shared_release`); for the last one it ends the value by the glue of its type and then gives up the `Weak` handle of the `Shared` handles (`_gopp_weak_release`), which frees the box when no `Weak` is left. The drop glue of a `Weak` is `_gopp_weak_release` alone. A handle that gave its value up is nil, and the glue does nothing for it. That nothing is changed through a `Shared` is the checker's (`E0492`). `tests/run/shared.gopp` copies handles into a slice, a map, a struct, a function literal and an interface value, locks `Weak` handles before and after the value ended, follows `Weak` links to a parent, and counts what is ended. **`Option[T]` today (`OWN-P9`, `OWN-P10`, `lower/option.rs`):** an option of a pointer, a handle, an interface value or a function value is that value, nil when it is unset; an option of any other type is `Type::Option`, the value and a flag. A value where such an option is wanted is the option that is set (`held_by` reads the type that the checker gave the expression, `set_option` works the value out for a new owner and makes `?T {value, true}`), and `nil` there is the option that is all zero. `o == nil` and `o != nil` read the flag (`nil_option`); a name that the checker narrowed is the first field (`Body::narrowed`). `o.IsNil()` and `o.Get()` are lowered where they are called, for both kinds of option (`option_asked`, `option_call`): `Get` gives a copy of what the option holds, made by the clone glue of its type and owned by the caller like a result of a call, and the flag; the copy of an option that is unset is all zero and nothing reads it. The glue of an option copies and ends what it holds if it is set (`Cloned::Held`). Two options are not compared with each other yet. `tests/run/options.gopp` has options as results, parameters, fields, elements and map values, of numbers, strings, arrays and a type with a `drop` method, and counts what is ended. `tests/run/unique.gopp` builds a list and a tree, copies, moves and lends handles, keeps them in a struct and a slice, and counts what is ended, where a panic leaves a function too. An interface value is copied and ended by the runtime, which is the glue of every interface type (§15). `tests/run/drops.gopp` ends values by every way out of a block, in a struct, an array and a slice, after a `move`, and as temporaries. **Equality and hash glue** (`lower/equal.rs`) are made the same way: `_GPTe<type>` takes two addresses and says whether the values are equal, `_GPTh<type>` takes an address and a seed and gives the hash. A value that is equal exactly when its bytes are (integers, booleans and pointers without padding and without a `_` field) is one `_gopp_mem_eq` or `_gopp_hash_bytes`; a struct is compared field by field, leaving the first difference at once and skipping the fields named `_`, and is hashed with each field seeded by the hash of the fields before it; an array goes through `_gopp_each_eq` and `_gopp_hash_each` with the glue of its elements; a float is compared as a float and hashed so that the two zeros have one hash. `==` and `!=` on structs and arrays and the cases of a `switch` over them call the equality glue with the addresses of two temporaries; a map whose keys the runtime cannot compare itself carries both functions in the record of its type. For an interface value both are functions of the runtime, which compare and hash the value that is held by the descriptor of its type (§15). The other places that copy elements call the glue as well: `x[i:j]` as a value, `append(s, t...)`, `copy`, `v, ok := m[k]`. A plain range variable is only read, so it is the element as it is (`RNG-1`).

## 8. Ownership, borrow, and concurrency checks — plus `-fpass-plugin`

`MoveCheck`, `BorrowCheck`, and `ConcurrencyCheck` run per function over the GIR CFG before drop elaboration, using `Info` ownership/borrow modes (which copies are made, which are skipped on a last use, and each `move(x)`) and the cross-package function summaries kept in export data: the borrow summaries (`OWN-B3`, `OWN-B9`, and for each pointer parameter whether the function borrows into what the pointee owns, `OWN-B10`) and, for each by-value parameter, whether it is **borrowed** or **owned** ([ADR-0041](../adr/0041-values-are-copied.md) rule 4):

- Every variable access is an explicit `Place` operand or destination; `AddrOf(place, mut)` is the sole borrow-creation rvalue; backward liveness of borrow locals detects conflicting writes/moves/drops in linear time; `go` and `s.Go` closure aggregates expose exact capture modes (`CON-1`–`CON-7`).
- **One fact per by-value parameter.** A parameter is **borrowed** when the function only reads it: it never writes to it, moves out of it, stores it, returns it or sends it. Anything else makes it **owned**. The caller makes any copy that is needed. It passes the argument as it is to a borrowed parameter and stays its owner; the callee does not destroy it. It passes a copy, or the value itself on a last use, with `move(x)` or for a temporary, to an owned parameter; the callee owns it and destroys it. A call that cannot see the body (through an interface, a `func` value, an itab or method-value thunk) treats every by-value parameter as owned; a function with borrowed parameters is reached from such a call through a generated thunk that calls the body and then destroys the arguments the body only read ([calling-convention.md](calling-convention.md)). An interface parameter has a second fact, **kept**: the function stores, returns or sends it (`TYP-7`). Only a kept parameter needs a box.

### 8.1 Middle-IR Pass Plugins (`-fpass-plugin`)

External GIR optimization, analysis, instrumentation, and equality-saturation (`egglog` `3.0.0`) passes plug into the middle end via Clang-style CLI flags ([ADR-0001](../adr/0001-implementation-language.md)):

- **CLI flags:** `-fpass-plugin=<path.{so,dylib,dll,wasm}>` (repeatable, executed in CLI order) and `-fplugin-arg-<plugin_name>-<key>=<value>`.
- **Stable ABI (`crates/gopp-plugin-api`):** Exposes `#[repr(C)]` `abi_stable::StableAbi` types (`GirPassPlugin_TO`, `PassStage::{PreDropElab, PostDropElab}`, `PluginMetadata`, `PluginDiagnostic`) and `GOPP_PLUGIN_API_VERSION`. Native shared libraries export an `#[export_root_module]` root module loaded by `crates/gopp-plugin-host` via `abi_stable` (`0.11.3`) + `libloading` (`0.9.0`), verifying ABI layout hashes and API versions at load time. Optional `.wasm` plugins exchange serialized `gopp_gir::Module` payloads via `rmp-serde` (`1.3.1`) inside a deterministic `wasmtime` (`50.0.1`) sandbox with zero host filesystem or network imports.
- **Mandatory safety firewall:**
  1. `MoveCheck`, `BorrowCheck`, and `ConcurrencyCheck` **always run before `PreDropElab` plugins**, so an external pass can never erase or hide an ownership, borrow, or concurrency violation.
  2. `gopp_gir::verify_module` (`V001`–`V085`) **runs immediately after every individual plugin invocation** (`PreDropElab` and `PostDropElab`). Any broken CFG, type, dominance, or cleanup invariant halts compilation with `E0440` (`err_gir_verify`), naming the offending plugin and rule.
- **Deterministic caching:** `gopp-plugin-host` hashes every loaded plugin binary and its sorted `-fplugin-arg-*` flags with `blake3` (`1.8.7`) into `.gopx` and object cache keys.

## 9. Verifier (`V001`–`V085`)

`gopp_gir::verify_module` runs after `lower_package`, after every `.gopx` decode, after every `-fpass-plugin` pass, after `elaborate_drops` / `inline_trivial`, and at the entry to `gopp-codegen-c`. It trusts no cached types, uses iterative worklists throughout, and runs in $O(|M|)$ time. Functions are checked in parallel; errors are reported in function order for any thread count. Errors format as `V027: fn main.f: bb3 #2: duplicate switch case 1`.

|---|---|
| `V001` | Every function exists and has a unique symbol name. |

| `V074` | Statements, terminators, and locals reference valid scopes; `Local::Origin` and `Local::ArgNo` satisfy inline-copy invariants. |
| `V075` | `Function::CC` equals `Function::Sig`'s `CallConv`. |
| `V076` | Indirect calls through `fn "C"` pointers pass and return scalars only. |
| `V077` | `Statement::Prologue` statements appear contiguously at the start of `bb0`. |
| `V078` | `Func` types with `has_env` carry `CallConv::Go` and `*u8` as parameter `0`. |

| `V085` | Every non-address-taken `Temp` local is initialized along all CFG paths reaching each read (verified via Lengauer-Tarjan dominator intervals + a backward search bounded to 32 CFG edges per read; a chain of single-predecessor blocks costs no edge, and a call initializes its destination only on its return edge). |

## 10. Monomorphization and hierarchy tables

- **On-demand `InstanceWalk` before GIR lowering:** Generic bodies are type-checked once in `gopp-sema`; `InstanceWalk` discovers all reachable function, type, and method instantiations in deterministic FIFO declaration order, applying `sema` type substitutions (`subst`) and re-resolving method selections on concrete types so `lower_package` never sees an uninstantiated type parameter.
- **Deduplication by mangled symbol:** `Box[byte]` and `Box[uint8]` produce the same mangled symbol (`gopp-mangle`) and share one GIR struct, one type descriptor, and one weak/ODR function definition (`__attribute__((weak))` / `static inline` / COMDAT).
- **Per-instance checks & complexity limits (`GEN-5`):**
  - Checks `Option[X]` where substituted `X` is already nilable (`E0446`) and `@Required` fields substituted with `Option` (`E0363`), identically in `gopp check` and `gopp build`; an implicit copy that an instance needs of a value without one is `E0453`. A value that an error or `ok` guards (`OWN-P10`) is checked once, in the generic body, where a type parameter counts as a type without a zero value (`E0493`): no instance is refused for it.
  - Enforces hard expansion caps (`E0449`, `GEN-5`): a type argument that generic code builds around a type parameter nests at most 48 levels and has at most 4096 parts as a tree; a package has at most `max(100_000, 8 * nodes)` instances, and its code with all its instances is at most `max(4_000_000, 64 * nodes)` nodes of syntax, where `nodes` is the number of expressions and statements of the package.
- **Today: instances of generic functions and of the methods of generic types.** A generic function of the package has no job of its own; each **instance** that is used has one (`JobName::Instance`). `Shared::instantiate` finds them in levels: the functions of the source name the instances that they use in `Body::instances` (a call, `f[int]`, a generic function that is given to a place), read in the order of the source; the instances found so far are the next level, until a level finds none. A use names an instance by its symbol (`Entity::FuncInstance`, `_GPI<function><type arguments>E`), so two lists of type arguments that are the same types, however they are written, make one instance, and an instance that nothing uses is not made. The instances come after the functions of the source in the module, in the order in which they are found, with the linkage `LinkOnceOdr`: every package that uses one has it, and the linker keeps one. The module does not depend on the number of threads: the uses of a level are read one after another, and only the bodies of a level are made side by side. **The body of an instance** is what the checker recorded for the generic body, read with the type arguments (`Body::instantiated` in `gopp-sema`): the checker keeps the type parameters as the body names them (`Body::type_params`), every type of every table is substituted, and the lowering then reads it as the body of any other function. What a type argument decides is decided there as for a body that is written with the type, by the function that the checker uses for such a body: whether a value that is put into an interface is boxed, is an interface value of the same methods that goes on as it is, or says its type another way (`Types::into_interface`); whether a place that gives its value to a new owner has a mark of how (`Types::given_is_marked`; a generic body marks the places whose type a type parameter decides and keeps the type, `Body::given_types`, and an instance has the mark only if its type has one); which method of the type argument a method of a type parameter is (`Body::param_methods`: found again by its name, so it may be one of a type that the argument embeds); and whether the receiver of such a call is marked, which it is only if that method gets a copy of it (`Body::receiver_marks`). The test `an_instance_is_the_function_that_is_written_with_its_type_argument` holds this: for each of many types and bodies, the instance is the same GIR as the function that the same lines make with a name of the type in the place of the type parameter, as a function and as a method of a generic type. A function literal belongs to the function that is lowered, so each instance has its own literals (`Literal::at` is the declaration; the symbol is that of the instance with the number of the literal). An instance as a value (`f := id[int]`) has the code `_GPTE<instance>` (`Entity::InstanceValue`). **Generic types:** an instance of a generic type (`Stack[int]`) is lowered like any declared type, with what it is declared as read with its type arguments, under the symbol of the instance. Its methods are found with the functions: each level also walks every type that its bodies are written with (the types of the expressions and of the variables, their parts, and what a declared type is declared as; each type once for the package), and every instance of a generic type that has methods gets a job for **each** of its methods, the types in the order of their symbols and the methods as they are declared (`JobName::Method` with the instance as the receiver, `_GPM<name>I<type><arguments>E`). A method that nothing calls is made too, because a value of the type may be asked for any of its methods where it is in an interface (`x.(I)` reads the methods of the type), and the glue of the type calls its `drop` and `Clone` methods. The body of such a method is the generic body read with the type arguments of the receiver, which the body names in its own way (`func (s *Stack[E]) ...`). `Shared::method(holder, name)` finds a method of a declared type or of an instance for a call, a method value, a table of methods and the facts. **Generic methods (`GEN-6`):** a method with type parameters of its own has an instance for each use (`x.m(args)`, `x.m[int](args)`), found like the instances of functions: by the type of the receiver, the name, and the type arguments of the method itself (`Used::Method`, `JobName::OwnMethod`, `Entity::MethodInstance`, `_GPIM<name><receiver><arguments>E`). The body is read with the type arguments of the receiver first, then its own. Such a method is in no table of methods (`GEN-7`). **Types that a generic function declares:** each instance has its own. `Body::instantiated` makes a new declared type for each type that the body declares (`Types::local_copy`), declared as the type of the generic body is with the type arguments and with the new types in the place of the old ones (`Replacing::rename`), so a type that names itself names its copy; the body is read the same way. The lowering gives the copy its number among the types of its name in the instance, so its symbol is that of a type declared in the instance (`_GPTig<n>_<name><instance>`), as the symbol rules ask. **Generic code of another package:** a package makes the instances of the generic functions and types of the packages that it imports itself, in its own module. The lowering is given those packages with their files (`Checked::imports`, `Imported`) and reads their generic declarations only: the rest is in their units. Every function that is lowered has a home, the package of its file (`Shared::home`, `FuncCx::home`), and what its body names is looked up there: a function, a variable, an import, a name that is not exported. So the body of `algo.Sum[int]` in the module of `main` calls `algo.bump` as a function of another package, by a declaration. A generic function is known by its package and its object (`Used::Func`, `JobName::Instance`) and its instance has the symbol of that package (`_GPIF4algoE3SumiE`), so the instance that two packages make is one for the linker. The bounds count the nodes of syntax of the package that is lowered. `gopp check` gives `check_instances` the same packages. **A generic method as a value** (`add := c.Add[int]`, or `var f func(int) int = c.Scaled` with the type arguments inferred) is a method value like any other: the receiver is worked out when the value is made and lives in a cell of the environment, and the code calls the instance (`Made::MethodValue` with the job of the instance; the symbol is `Entity::MethodInstanceValue`, the instance under the wrap of a method value). Not lowered yet (`E0439`): a generic type that a generic function declares. **The checks of an instance:** what a type argument makes of the types of an instance is held to what the types ask, where the instances are found, so `gopp check` reports it too. The body of an instance that writes an option of a type which has nil already (`var o Option[T]` with a slice, a map, an interface for `T`) is refused with `E0446` (`OWN-P9`), and an instance of a generic type whose `@Required` field of a type parameter is an option there with `E0363` (`TYP-15`; `Shared::unfit`, by `Types::has_own_nil`, `Types::is_required` and `Types::is_option`, which the checker uses where the type arguments are written). The report is at the use that asks for the instance, with the uses that led there. The checker reports both itself where a declaration says it (a field or a result `Option[T]`, a `@Required` field `T`) and the type arguments are written; the search adds what only a generic body says, and what one generic function passes to another. A copy that an instance does not write, of a value that has none there (a variable of a loop that a literal keeps, an exchange of three places), is `E0453` where the lowering needs it, with the same notes; in a function that is no instance it is `E0452`. Not checked yet: the uses of a parent that a type argument must have (`E0316`, `E0323`), which wait for the lowering of types with parents. **The bounds (`E0449`):** `Shared::instantiate` holds the instances to the bounds above (`Limits`), where it finds them. A use in the body of an instance whose type argument is built around a type parameter in the generic body (`[]T`, `Pair[T, T]`; the two bodies are compared, so `T` passed on as it is and a type that the source writes have no bound) is measured with its real types: the levels and the parts of a type are kept for each type (`too_large`), so a type that is shared by many is measured once. An instance of a generic type that the body of an instance names and that no body writes (`written_in` has the types without a type parameter of the generic bodies) is measured the same way. Each new instance counts, with the nodes of syntax of its declaration (`decl_nodes`). Past a bound is one report at the use, `cannot instantiate F: <the bound> (GEN-5)`, with the uses that led there, the nearest first (`Job::by`, at most 16); no instance is made after it, and nothing of the package is lowered. `gopp check` runs the same search without lowering (`gopp_gir::check_instances`) for a package without another error, so it reports what a build reports. `tests/run/generics_owned.gopp`, `tests/run/generic_types_owned.gopp` and `tests/run/generic_methods.gopp` run them.
- **Today: `@Operator` and `@Convert` methods (`EXP-16` to `EXP-20`, `lower/operator.rs`).** Each `@Operator` method of a type is a function of its own (`JobName::Operator(type, n)`, the `n`-th of the type in the order of the declarations; the checker says which declaration is which in `Package::operators`). Its symbol is that of the operator with what it takes (`Entity::Operator`, `_GPTo<op_Name><type>L<parameters>E`, `opr_` for a `@Right` method), so two methods of one name are two functions. `Shared::operator(holder, n)` finds one for a call (`CalleeKey::Operator`), also of a type of a package that is imported; the one method of its name is in `Shared::methods` too, and is called by its name and is a value like any method. An expression in `Body::operators` is a call of its method by the code of every method call (`method_call`): the operand with the method is the receiver, the one on the right for a `@Right` method; `a != b` is not what `Eq` gives, and an order is what `Cmp` gives against zero. `x op= y` (`Body::op_assigns`) calls the method that changes `x` where it is with the address of `x`, or stores what the method of the operator gives. `x[i]` is `Index`, `x[i] = v` is `SetIndex` with the value last (`Body::index_stores`), `T(a)` is the `@Convert` method by its name, and a case of a switch is compared by `Eq` (`Body::case_operators`). The operands are lent or given as the method's parameters ask, as in any call. Not lowered yet (`E0439`): an operator method of a generic type or of a type parameter (`GEN-13`), `range` by `Iter`, a `@Right` operator whose left operand does more than read, `x op= y` without an in-place method for an `x` that does more than read, `x[i] op= v`, and a switch by `Eq` whose tag does more than read. `tests/run/operators.gopp` runs them, with the order in which the operands are worked out.
- **Today: types with parents that have no type table (`TYP-16`, `TYP-17`, `TYP-20`, `TYP-22` to `TYP-24`).** The struct of a type with parents has the part of each parent first, in the order of the `@Extends` and under the name of the parent, and then the fields of the type: no word more (`Memo::strukt`; `Memo::leads` has the number of parents of each such struct). A step of the checker is a field of the type, which counts after the parts, or a parent with the bit `PARENT` (`FuncCx::part`, which `steps` and the code of the methods in tables of interfaces use). A method of an ancestor is called with the part of that parent as its receiver, by the way that the selection has, and so is its `@Operator` method (`Types::ancestor_path`). `base` and `base[Parent]` are the receiver of the method (`Shared::base_of`: the name `base` that denotes nothing), in a function literal too, where the checker counts the receiver as captured; `base.M()` is the method of the parent itself. In a struct literal a field of an ancestor is set in the part that has it, after the parts that the literal names are made (`inherited`). The glue copies and ends the parts of the parents with the fields: a value ends child first, its own fields from the last to the first and then its parents from the last to the first (`OWN-R2`); equality, hashes and the comparison by bytes take the parts of the parents first. An interface table has the methods of the parents (`TYP-23`), and an instance of a generic parent gets its methods like any instance that a type names. `tests/run/parents.gopp` runs these, with the order in which the parts end.
- **Today: type tables (`TYP-22`, `EXP-13`, `EXP-14`, `lower/table.rs`).** A type with a method that may be replaced starts with the address of its table: the first word of its first parent if that has a table, a word of its own in front of its parents otherwise (`Shared::own_table`, `Memo::tabled`). The part of every other parent with a table starts with the address of a table of its own (`Shared::tables_of`). A table is a `LinkOnceOdr` global, `_GPTv<type>` for the start of a value and `_GPTs<type><parent>` for a part: a word that says how many bytes the part is from the start of the value, negative, the address of the record of the type of the value, then the code of each method that may be replaced, in the order of `Shared::slots` (those of the first parent, then the `@Virtual` and `@Abstract` methods that the type declares). What a table has for a method is a function `_GPTt<bytes>_<method>` (`Entity::Adjusted`, `Made::Adjusted`, `adjusted_body`): it takes the address of the part, makes it the receiver of the method that the value's type has, calls the method, and ends what the method only reads of the arguments, which a call through a table gives away as a call through an interface does. A method without a body has a null there. **A call** of such a method through a pointer or a handle (`table_called`) finds the part whose type declares the method first (`Shared::slot_of`), reads the code from the table of that part and gives it the address of the part. A call on a value, whose type is known, is a call of the method; so is `base.M()`. **A pointer to a value** where one to a part of a parent fits is the address of that part (`upcast`, from `rvalue_plain`; a `Unique` or a `Shared` is lent first). **The addresses are set late:** a value that is made all zero has none, so `set_tables` writes them where they are first needed, if the first word is null: before a call through a table, before a pointer becomes one to a part, and before a method of a parent gets its part as a receiver, in the code of an interface table too. A value without them is of the type that the code names there, because every pointer to a part of a larger value was made from one to the larger value. **The record of a type** with a table is a global `_GPTs<type><type>` with the name of the type, the size and the glue of a value and, for each ancestor with a table, the record of that ancestor and where its part starts (`whole`, `Shared::parts_of`); every table of a value names the record of the type of the value after its first word. **`p.(*T)`** on a pointer or a handle (`EXP-15`, `part_asserted`) asks the runtime for the part of `T` in the value that `p` points into (`_gopp_part_of` in `runtime/table.c`: the start of the value by the first word of the table, then the type itself or the parts of its record), ends the program by `_gopp_panic_part` if there is none (`pointer conversion: *main.Shape points to main.Square, not main.Tile`), and gives the address with `ok` in the form with two values. A type switch on such a pointer asks the same for each case (`part_switch`); the variable of a clause with one case is the address that the case found. **Handles of a parent (`EXP-13`, `OWN-R2`, `OWN-R6`):** a `Unique`, a `Shared` or a `Weak` of a child where the same handle of a parent is wanted is the handle with the address of the part of the parent (`handle_upcast`): it is copied or given like any value first, and stays one word. `NewUnique` and `NewShared` make the handle of the type of their value, whatever the place takes. The record of a type also has the size of a value and its drop and clone glue. The glue of a handle of a type with a table asks the runtime first (`runtime/table.c`): `_gopp_whole_end` ends the whole value by the glue of its record and frees its box, `_gopp_whole_copy` makes a box with a copy of the whole value and gives the address of the same part in it, and `_gopp_part_retain`, `_gopp_part_release`, `_gopp_part_weak_retain`, `_gopp_part_weak_release` and `_gopp_part_lock` count at the start of the whole value, where the counts are. A value without the address of a table is of the type that the glue names, and the runtime leaves it to the glue. An option of a pointer or of a handle that is unset stays unset: both conversions test for nil first. Not lowered yet (`E0439`): a method that may be replaced as a value; `p.Clone()` through a pointer to a parent. Known gap: a `drop` method of a parent that calls a method which the child replaces runs the child's method after the child's fields ended. `tests/run/tables.gopp`, `tests/run/downcasts.gopp`, `tests/run/panic_downcast.gopp`, `tests/run/parent_handles.gopp` and `tests/run/parent_options.gopp` run these.
- **Hierarchy vtables (`P04.22`):** Types with parents (`@Extends`) and `@Virtual`/`@Abstract` methods (or tagged secondary parents) emit static vtable globals (`Struct("pkg.T.vtable")` at offset `0` — sharing a polymorphic C++ primary base's vptr slot when extending C++, `TYP-28` — plus secondary `(Child, Pi)` tables). Each vtable carries `offset_to_top` (`isize`), complete-object descriptor/drop/clone hooks, parent downcast tables, and virtual method slots (with `recv += offset_to_top` thunks for secondary overrides), keeping `Unique[P]`, `Shared[P]`, and `Weak[P]` single 1-word pointers (`TYP-19`).

## 11. Checker records consumed by GIR lowering

The tables are kept for each top-level declaration (`gopp_sema::Body`, in `Package::files[i].bodies[j]`), keyed by the expression. `gopp_sema::info_text` prints them one entry per line in source order (`gopp check -emit=info`); the text is the same for any number of threads. A generic body has four more records for its instances, which `info_text` does not print: `Body::type_params`, `Body::given_types`, `Body::param_methods` and `Body::receiver_marks` (section 10).

| `gopp_sema::Info` table | How `gopp-gir` uses it |
|---|---|
| `types`, `values` | Expression `TypeId`s and compile-time `Constant`s |
| `defs`, `uses` | `LocalId` resolution, direct `FuncId` callees, builtins |

## 12. Text printer (`-emit=gir`)

`gopp build -emit=gir` and `gopp gir dump file.gopx` emit identical, deterministic human-readable GIR text:

```text
module "command-line-arguments"
file 0 "hello.gopp"

declare fn write(_1: i32, _2: *u8, _3: u64) -> i64 [c, external, nounwind]

fn main.main() -> () [go, external] {
  let _0: ()
  let _1: string
  let _2: i64
  bb0:
    _1 = const str#0 "hello\0A"  ; hello.gopp:7:2
    _2 = call const fn @write(const 1: i32, copy _1.0, copy _1.1) -> [return: bb1, unwind: unreachable]  ; hello.gopp:7:2
  bb1:
```

## 13. Binary `.gopx` serialization

`crates/gopp-gir/src/gopx.rs` serializes GIR modules into `.gopx` export/cache containers using **`postcard` (`1.1.3`) + `zstd` (`0.14.3`) + `blake3` (`1.8.7`)** ([ADR-0001](../adr/0001-implementation-language.md)):

```text
file = magic "GOPX" (4B) | format_version u32 LE | compiler_version str
     | blake3_digest [u8; 32] | uncompressed_len u64 LE
     | zstd_frame(postcard(ModuleEnvelope { tables, types, globals, func_decls, func_bodies, index }))
```

- **Selective per-function decoding:** `index` stores byte offsets for each `func_bodies[i]` entry so cross-package generic instantiation and inlining (`P06`) decode module tables plus a single requested function body without deserializing the rest of the package.
- **Deterministic & corruption-safe:** Type and symbol IDs are assigned in canonical traversal order (zero hash-iteration order dependence); every decoded index, enum discriminant, and slice bound is validated and passed through `verify_module` (`V001`–`V085`) so truncated or bit-flipped `.gopx` inputs always return a clean error and never panic.

## 14. Debug scopes (`Function::Scopes`)

Every statement and terminator carries a `Span` and a `ScopeId` into `Function::Scopes` (`0` = function root; `N > 0` = `Scopes[N - 1]`, ordered parent-before-child). `DebugScope::Block` represents lexical `{ ... }` blocks; `DebugScope::Inlined` represents trivial-inlined call sites (`V073`, `V074`). Struct field names live in a side table (`field_names`, persisted in `.gopx`) so structural layout identity stays fast while `gopp-codegen-c` emits exact C23 member names for DWARF ([debug-info.md](debug-info.md)).

## 15. Language lowering details

- **Strings, slices, maps, and custom allocators ([ADR-0026](../adr/0026-no-small-string-optimization.md), [ADR-0027](../adr/0027-mimalloc-global-allocator.md), [ADR-0029](../adr/0029-slice-and-map-allocator-word.md), [ADR-0032](../adr/0032-shared-buffers-and-borrow-engine.md), [ADR-0041](../adr/0041-values-are-copied.md)):**
  - `string` is `{ptr, len, backing}` (`24` bytes on 64-bit); `[]T` is `{ptr, len, cap, backing}` (`32` bytes on 64-bit), where the heap/arena `backing` of a slice points to the header `{alloc_cap, alloc}` at the start of the buffer (`alloc == null` selects global `mimalloc`; non-null points to a C-ABI `{alloc, resize, free}` allocator vtable). A slice buffer has one owner and no reference count: the owner frees the buffer and drops exactly the elements `ptr` to `ptr + len`.
  - Slicing a `string` (`s[i:j]`) shares `backing` in $O(1)$ (`OWN-S1`). Slicing a `[]T` or an array (`s[i:j]`, `arr[i:j]`) is a value: a new slice with copies of those elements, and the copy is skipped when the program cannot notice it (`OWN-S2`). So `s = s[i:j]` works in place, and the elements it cuts off are dropped at that statement (`SLC-9`). `&s[i:j]` and `&arr[i:j]` are `*[]T` views of the same elements; a view and `unsafe.Slice` set `backing = null` and `cap = len` (a view is borrow-checked: it cannot outlive `s`, and `s` cannot be assigned, grown or moved while it is in use, `SLC-8`). The four-word record of a view is a hidden local of the block that holds the statement; a `defer` extends it like any local. A view written directly in a `return` is built in the caller's frame, in the hidden place that every `*[]T` result has ([calling-convention.md](calling-convention.md)). Dropping it frees nothing while `backing == null`; if code assigned or appended through the pointer, the record owns the new buffer and the drop frees it. `s` is never changed by that. `append` grows in place when `backing != null && len < cap` and otherwise allocates a fresh buffer in `alloc` (`SLC-2`).
  - `map[K]V` is a 1-word `gopp_map*` pointer to a header `{alloc, count, ...}` with no reference count; `m[k] = v` on an addressable slot initializes `nil` maps in place via `&slot` (`OWN-P9`, `PAR-1`), and `range` tracks active iterators to panic deterministically on concurrent `insert` or `clear` (`RNG-4`).
- **Strings today:** `s[i]` is a bounds `Assert` against `Len(s)` and an `Index` projection; `s[i:j]` copies the string value, asserts `j <= len` (`SliceAlen`) and then `i <= j` (`SliceB`), and builds `{AddrOf(s[i]), j - i, s.backing}` as an `Aggregate`, so no byte is copied; `+`, `==`, `!=` and the four orders are calls of the runtime ([runtime.md](runtime.md)), and a `switch` over strings is a chain of such calls; `string(r)` is a call too.
- **Slices today** (elements without a slice inside; the rest needs the copy glue of `P04.09`): a place whose value the checker marks as copied (`Info::var_modes`) gets `_gopp_slice_copy` where it is given to its new owner: an assignment, an argument, a receiver by value, a result. `s = append(s, ...)` and `s = s[i:j]` are found by their shape (the same place on both sides) and work on `s` where it is. `x[i:j]` builds the header `{AddrOf(x[i]), j - i, ...}` after its checks, the high bound against the length (`SLC-13`): as a value it is then copied, in place it keeps the backing and the room, and `&x[i:j]` is the address of a record with no backing and no room. An element that an assignment stores to is one of the slice as it was when the place was worked out. `make`, `append`, `copy`, `clear`, a literal and the conversions between `string` and `[]byte` or `[]rune` are calls of the runtime, which takes a slice by the address of its record ([runtime.md](runtime.md)).
- **Maps today** (keys that the runtime compares itself, values without a slice or a map inside; the rest needs the glue of `P04.09`): every operation is a call of the runtime ([runtime.md](runtime.md)) with the record of the map type, which the lowering builds from the checked type of the map, since every map type is the one type `*gopp.map` in GIR. A read copies the value into a slot; an entry is no place. `m[k] = v` works out the place that holds the map and the key with the other operands of the assignment, and at its store calls `_gopp_map_set` with the address of that place and writes through the pointer that comes back; `m[k] op= v` reads, works out the value, and then stores the same way. A place whose value the checker marks as copied gets `_gopp_map_copy` where it is given to its new owner.
- **`range`:** the range expression is worked out once, into a slot of its own; a hidden counter of the loop is compared with the count in the head block; each pass has a scope of its own for its variables, which get copies of the counter and of the element, so a body that changes them does not change the loop; `continue` goes to the block that steps the counter. Over an integer the counter has its type. Over an array the count is its length, and without a variable for the elements the array is not worked out at all; an array whose elements are copied by their bytes is copied before the loop, as in Go, and any other is walked where it is (`RNG-6`), as is an array behind a pointer. Over a string each pass calls `_gopp_string_decode`, which gives the code point and its width, and the counter steps by the width. Over a slice the loop walks the elements of the slice as it is when the loop starts. Over a map the head block calls `_gopp_map_iter_next`, which copies a key into a slot of the loop and gives the address of its value, which the pass copies; the scope of the loop holds the walk, and every way out of that scope (the end of the loop, `break`, `return`, a `goto`, a `continue` of an outer loop) calls `_gopp_map_iter_end` where it marks the variables of the scope dead. With `&v` (`RNG-1a`) the variable of a pass holds the address of the element (`AddrOf` of the indexed place, or the pointer that the runtime gave for a map), and every use of `v` is what that pointer leads to: nothing is copied, so the loop also walks elements that hold a slice, and an array is walked where it is. Channels and functions are not lowered yet.
- **Evaluation & assignment order (`EXP-3`):** Two-phase evaluation evaluates LHS index/pointer operands and RHS expressions left-to-right into temporaries before executing bounds-checked stores left-to-right, using replay scopes (`derive_dest`, `resolve_dest`) so container growth on an earlier tuple element never leaves a dangling slice/map pointer. An operand that is read before a later operand of the same expression calls a function is copied into a temporary first; an aggregate that is stored behind a pointer, or that reads the variable it is stored in, is built in a temporary (`V057`).
- **Pointers (`OWN-P5`, `EXP-7`):** a `*T` where only a `T` fits is read through the pointer, an assignment that `Info::writes_through` lists stores through it, and no nil check is made (a pointer is never nil).
- **Control flow:** a `switch` whose cases are integer constants is one `Switch` terminator; any other is a chain of comparisons in source order. Leaving a scope by any way emits `StorageDead` for its variables, a backward `goto` also for the variables of the label's own scope that were declared after the label. Before a function is finished, unreachable blocks are dropped, blocks that only jump on are bypassed, and the rest are laid out in the order in which they were first written.
- **Closures & `func` values (`CLO-1`–`CLO-8`):** `{code, env}` (`16` bytes); iterative escape analysis (`KeepTable` + `may_hold`) keeps non-escaping closure environments on the stack (`Immortal` tag) and allocates heap environments + refcounted capture cells for escaping closures (per-iteration cells on `for` loops, `CLO-8`), rejecting escaping stack/arena borrows (`CLO-3a`, `OWN-B5`).
- **Interfaces & itabs (`TYP-5`–`TYP-9`):** `gopp.iface` = `{itab, data}` (`16` bytes); per-type `_GPTi<type>` descriptors and `_GPTa<type><iface>` static itabs (with runtime cached `get_itab` for interface-to-interface conversions); inline storage for `<= 1`-word `OWN-C1` values and single-owner boxes with no refcount for everything else; a copy of an interface value copies the value it holds (`TYP-5`).
- **Static data today.** A global with `Parts` is in the image of the program as it is said: nothing runs to make it. A leaf of a type is a scalar, a pointer, a string or a slice; a tuple, a struct, an array and an option are their parts (`TypeInterner::leaves`). A part is an integer, a boolean, a string of the module, null, `Zero`, or the address of a function or of a global, also of the global itself. The emitter declares every global before the functions, which name them, and writes the definition with its initializer after the prototypes of the functions, which the data names; a global that the program never writes is `const`. In the merge a global has its data from the first run that says it, and what the data names (types, strings, functions, other globals) gets its place in the module then. The descriptors of types are the only static data so far; a first value of a package variable is given by code when the program starts (below), and composite constants as static data are still to come (`P04.31`).
- **The start of a program today (`INI-1`).** Each step of the start that the checker found (`Package::init_order`: the variables on the left, the value on the right, in the order of what the values need, as in Go) is a function of its own: a job like a function of the source (`JobName::Initializer`), so it is lowered in a run with the others, its function literals are numbered with its declaration, and the instances that it uses are found. The function works the value out and gives each variable its part as a new owner; a variable named `_` gets none, and what the value made and no variable took ends there. Nothing ends a variable of a package (`INI-5`). Its symbol is that of the function with the number of the step, from 1, of what starts the package (`_GPC<n>_J<package>`; appendix A), and a function literal of a first value is one of its variable (`_GPC<n>_R<variable>`), or of that function where no variable has a name. What starts the package, `_GPJ<package>`, calls the steps in order (`lower_start`, in the module of the globals), and the unit of C calls it before the `init` functions of the package, which run before `main`. A panic in a first value goes up as from an `init` function: it is printed and the program ends with the status 2 (`INI-4`). Every value is given by code, a constant too. The packages that a program imports are started first, each after those that it imports ([targets-and-linking.md](targets-and-linking.md)). `tests/run/program_init.gopp`, `tests/run/program_init_owned.gopp` and `tests/run/program_init_panic.gopp` run it.
- **Interface values today (`TYP-5`, `TYP-6`, `TYP-8`, `TYP-9`).** Every interface type is the one struct `gopp.iface` in GIR, `{itab, data}`. A value that is put into an interface (`Info::iface_conversions`, or `any(x)`) is worked out as its own type for a new owner, so it is copied, or given on its last use and with `move(x)`, as in any assignment; then it goes into the second word itself if it owns nothing and is at most a word, and into a box of `_gopp_iface_box` otherwise. The first word is the address of the descriptor of the type, a `LinkOnceODR` global `_GPTi<type>` of the type `gopp.type` with static data: its own address, the size, the marks (in the word itself, compared with `==`, a type with a name), the clone, drop, equality and hash glue of the type (null where the bytes say all), the name, the table of its methods, and what a value of it is for the text of a panic (`kind`; [runtime.md](runtime.md)). The lowering says the descriptor in the module of the run that needs it; the merge keeps one. The glue of an interface type is four functions of the runtime, so an interface value in a slice, a map (as a key too), a struct or an array is copied, ended, compared and hashed as any other value there. `x == nil` reads the first word; any other `==` is `_gopp_iface_eq`. `x.(T)` compares the first word with the address of the descriptor of `T`: the form with one value ends the program by `_gopp_panic_assert` if they differ and reads the value where the interface value holds it, so only what takes it as its own makes a copy; the form `v, ok := x.(T)` gives a copy and `true`, or the zero of `T` and `false`. A type switch looks into its value once and compares the first word with one descriptor after another, with null for `case nil`; the variable of a clause with one type is a copy of the value that is held, and in any other clause a copy of the interface value (`TYP-9`: the copy is not skipped yet when the variable is only read). **With methods:** the first word of a value of an interface with methods is the address of a table, a `LinkOnceODR` global `_GPTa<type><interface>` with static data: the descriptor of the type, then one function for each method of the interface, in the order of their names. The function is `_GPTI<method>` in the table of a type and `_GPTp<method>` in the table of the pointers to it; the package makes each once, with the glue. It takes the address of the second word of the interface value and the arguments of the method, finds the value (the word itself for a value that is in the word, what the word points to otherwise), and calls the method: with the address for a pointer receiver, with the value for a receiver by value, which is a copy if the method does more than read it. So a method that is called through an interface works on the interface's own value and may change it (`TYP-5`). A call `x.M(args)` works out the place of `x` and the arguments, each for an owner of its own because nothing is known of the method that runs, then reads the code from the table (with a nil check where the interface may be nil) and calls it with the address of the second word. **Arguments without a box (`TYP-7`):** besides the fact that a function only reads a parameter (`Facts::lent`), a parameter of an interface type has the fact that the function calls methods through it and does no more to it (`Facts::worked`). Both are lent: the function does not end them. A value that is put into an interface for a lent parameter gets no box: the interface value is `(table, &value)`, the address of the value where it is. For a parameter that is only read that is the caller's variable itself, if nothing can change it during the call, and a copy in the caller's frame otherwise (what a call gave is moved to a slot of its own first, because nothing points into the slot that a call puts its result in, `V066`); for a parameter that methods are called through it is always a value of the caller's own, in its frame, which ends with the statement, so what a method changes is never the caller's variable. An interface value that is passed to such a parameter is a copy of its own too, or the value itself on its last use; the last use of a parameter that the function was lent this way goes on as it is. A value that is in the word itself is passed as ever. The facts are those of one function alone: a function that only passes its parameter on reads it, so what it passes on to a function that calls methods is a copy. A call through a table of methods knows no facts and gives every argument away, which the function of the table ends (`PAR-10`). `x.(T)` and a type switch on such a value read the descriptor through the table. Every look into an interface value reads the descriptor through the first word, whether that is a descriptor or a table, so a value of an interface with methods is a value of `any` as it is. **Between interface types:** the checker notes where an interface value is given to a place of an interface type with other methods (`Info::iface_changes`), also for one of the several values of a call (`Info::part_conversions`, which has the values that are put into an interface there too). Such a value gets the table of its type for the methods of the place from `_gopp_iface_table`, which makes the table the first time a type is asked for an interface type and keeps it. For that the descriptor of a type has the methods of the type (`_GPTm<type>`: the key of each method and what a table holds for it, in the order of the keys), and an interface type has a global with its name and the keys of its methods in the order of its tables (`_GPTn<interface>`). A key is the name of the method, the package of a name that is not exported, and the symbol of its type. A value has the methods with a pointer receiver too (`TYP-5`). `x.(I)` and `case I` ask the runtime the same way: the form with one value ends the program by `_gopp_panic_assert_iface` if the value lacks a method or is nil, and gives the same value with the new first word, of which a new owner takes a copy. Two interface values of different interface types are compared as they are. Not lowered yet (`E0439`): a value of a type that has a method which cannot be called yet (a method of a generic type of another package), a method value `x.M`, a complex number in an interface, and the `kept` fact of the checker, which would let a value that is not `Send` be lent (`TYP-7`, `CON-12`).
- **Function values today (`CLO-1` to `CLO-9`).** A function value is two words, `(code, env)`: the code is a function of the Go convention that takes the environment first (`fn env(*u8, ...)`), and the environment is null for a function that captured nothing. A function literal is a function of its own, `_GPC<n>_<function>`, numbered from 1 in the order of the source among the literals that are written directly in the same function or literal (`Shared::number_literals`); a function names it and it is lowered right after that function, so the module does not depend on the threads. A function of a package that is used as a value (`f := add`) has as its code `_GPTE<function>`, which the package makes once with the glue: it calls the function with what follows the environment. A call through a function value works out the value first and calls the code with the environment and the arguments; it knows nothing of the function that runs and gives every argument away (`PAR-10`), so `_GPTE<function>` ends what its function only reads. A parameter of a function type that is only called is lent. The copy of a function value is one more value that shares its environment and its end one less, counted by `_gopp_func_clone` and `_gopp_func_drop`, which are the clone and the drop glue of every function type; an environment starts with the count and with the function that ends what it holds ([runtime.md](runtime.md)). A function value is put into an interface like any value of two words. **Captured variables:** a variable that a function literal which may outlive it uses lives in a **cell** (`Facts::celled`, from `Info::captures`): a block of the heap with a count and then the variable. The function that declares the variable makes the cell where the variable is declared (`_gopp_cell_new`; a parameter is moved into its cell at the start), names the variable as what the cell holds (the same way as `&v` of a range clause, so it is never moved out of and never counted as quiet), and lets the cell go where the scope of the variable is left. A literal that is not framed (below) and uses variables has an environment, `_gopp_env_new`: the count, the number of cells, and for each variable the address of its cell, which the environment shares, and the drop glue of the variable. The code of the literal starts by naming each of those variables as what the cell in its environment holds. The last function value that goes lets the cells of its environment go, and the last that lets a cell go ends the variable. So a variable lives as long as anything uses it, and every literal sees what the others did to it, as in Go. Each pass of a `for` loop with three clauses goes on with a new cell for a variable of the loop that a literal uses, which has a copy of what the variable held, and each pass of a `range` loop declares its variables anew (`CLO-8`). The copy for the next pass is one that the program does not write: if the type of the variable cannot be copied, the lowering refuses it at the loop (`E0452`), with a note at the first literal that uses the variable and is not framed (`Facts::later`). **Framed literals (`CLO-1`):** a literal whose value cannot outlive the variables that it uses has its environment in the frame of the function that makes it: a temporary with the count `GOPP_ENV_IN_FRAME`, which the runtime never counts or frees, and the address of each variable where it is, or of its cell if another literal put it in one. Nothing is allocated, and the variables stay ordinary variables of the function. The facts of the function say which literals are framed (`Facts::framed`): one that is called where it is written; one that a `defer` statement calls and that uses only variables of the whole function (parameters, results, what the outermost statements declare), since the others are gone when it runs; one that a variable is declared with which is only called, never named otherwise, never assigned, and used by no other literal; and one that is an argument for a parameter which the function that is called is lent (it only calls it), which is known once every function of the package has its facts (`Facts::lend`). A variable lives in a cell exactly when a literal that is not framed uses it or a method value has its address (`Facts::settle`). The facts look at the literals that are written directly in a function of the package; a literal inside another literal is treated as one that escapes. The code of a framed literal names each variable as what the address in its environment leads to. **Method values and method expressions (`CLO-5`, `CLO-5a`):** `x.M` is a function value whose code is `_GPTV<method>`, which the package makes once, and whose environment has a cell with the receiver as it is worked out where the value is made: a copy of `x` for a method that takes a value (the value itself for a temporary), the address of `x` for a method that takes an address, the interface value for a method of an interface. A variable whose address a method value has lives in a cell (`Facts::celled`), which the environment shares, so the variable lives as long as the value. The code reads the receiver from the cell and calls the method, through the table of the interface value for a method of an interface. `T.M` and `(*T).M` are function values without an environment whose code `_GPTE<method>` takes the receiver after the environment; `(*T).M` of a method that takes a value is `_GPTETp<method>`, which reads the value through the address. Not lowered yet (`E0439`): a literal that is not framed and uses another name of an element (`&v` of a range clause), a method value of an interface type without a name or of a type of another package, a method expression of an interface or of an embedded type, and `go` of a function value. **`defer` of a function value (`CLO-3b`, `CLO-7`):** `defer f(args)` for a function value, a function literal too, keeps the value and the arguments in slots of the function, each worked out at the statement; where the function is left the code of the value is called with its environment and the arguments, which it is given, and the value ends. A deferred literal reads its variables in their cells, so it sees what they are when it runs, may change a result that has a name, and a variable of a block that it uses lives until the call was made (`PAN-3`). A function value that uses the variable that holds it keeps itself alive (`CLO-6`).
- **Functions with `...` today (`PAR-7`).** The last parameter of a function with `...` is a slice like any other, with the same facts. A call that gives its arguments one by one makes the slice where the call is written: the arguments of the other parameters are worked out first, then each of the last ones as an element for a new owner (a copy, or the value itself for a temporary and on its last use), then `_gopp_slice_make` makes a slice of exactly that many elements in a temporary that owns it. A function that only reads the parameter is lent the slice, which ends with the statement, and where a panic leaves it; any other function is given it. Without arguments for it the slice is nil and nothing is made. `f(xs...)` passes `xs` as any slice argument: the slice itself for a function that only reads it, a copy otherwise, so a function never writes into the slice of its caller. `f(g())` gives the first results of `g` to the other parameters and the rest to the slice. A method with `...` is called the same way, through an interface and as a function value too: the function of the table and `_GPTE<function>` take the slice as it is. `defer f(a, b)` makes the slice at the statement and keeps it in a slot like the other arguments. Not lowered yet (`E0439`): `defer` of a function value with all the results of one call. The slice of a parameter that is only read is made on the heap as well, for now. `tests/run/variadic_owned.gopp` counts what is ended, where an argument or the function panics too.
- **Stack discipline:** Recursive AST walks use `stacker::maybe_grow` (`0.1.25`), while every GIR pass, type walk, verifier check, `.gopx` codec, and C23 emitter walk is strictly iterative.
